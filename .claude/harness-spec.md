# harness-spec — Congress API

이 저장소의 하네스가 **무엇을, 왜 그 층에 두었는지**의 기록이다. 컴포넌트 목록은 `audit_harness.py`가 디스크에서 읽어 오므로 여기 적는 값은 목록이 아니라 **판단**이다 — 다음 사람이(또는 다음 세션의 내가) 같은 자리를 다시 고민하지 않도록.

## Goals

**클로드가 국회를 실제로 아는 상태를 만든다.** 조회 자동화가 아니다. "이 의원이 발의한 법안 전부", "이 법안에 반대표를 던진 의원 명단"처럼 **완결성이 답의 일부인 질문**은 모집단을 손에 쥐어야 답할 수 있고, 검색 결과 몇 개로 대체되지 않는다.

그래서 하네스가 실제로 해야 하는 일은 둘뿐이다.

1. **국회 질문이 오면 다른 데로 새지 않게 한다.** WebSearch는 완결성을 보장하지 못하고, 국회 OpenAPI는 웹사이트와 값이 어긋난다. 둘 다 그럴듯한 답을 주기 때문에 막아 두지 않으면 조용히 그리로 간다.
2. **DB를 아는 데 드는 비용을 0으로 만든다.** 스키마 한 번 읽는 것으로 관계와 함정을 다 알 수 있어야 한다.

## 층 배치의 근거

이 하네스의 중심 결정은 **문서를 스키마 안에 두기로 한 것**이다.

`sqlite3`에는 `COMMENT ON`이 없지만 `CREATE TABLE (…)` **괄호 안**의 `--` 주석은 `.schema` 출력에 그대로 남는다. 그래서 컬럼의 함정을 주석으로 쓰면 그것이 곧 문서가 되고, 조회하는 쪽이 별도 문서를 찾아 읽을 필요가 없다. 이건 harness-creator가 말하는 "instruction 대신 interface"의 이 프로젝트판이다 — 주석은 `.schema`를 부를 때마다 다시 읽히고, 컴팩션 뒤에도, 서브에이전트 안에서도 살아 있다.

> ⚠️ **주석은 반드시 괄호 *안*에 있어야 한다.** SQLite는 문장을 파싱해 다시 쓰면서 `CREATE TABLE` **앞**의 주석을 버린다. 초안은 테이블 설명을 전부 위에 두어 238줄 중 70줄(29%)이 `.schema`에 도달하지 못했다. `db.py selftest`의 `COMMENT_GUARDS`가 이걸 잠근다.

그 결정이 나머지를 정한다.

| 두는 곳 | 담는 것 | 근거 |
|---|---|---|
| 스키마 주석 (`db.py`의 `SCHEMA`) | 컬럼의 의미와 함정 | `.schema`가 1차 인터페이스다. 여기 있으면 공짜로 다시 읽힌다 |
| `SKILL.md` | **스키마가 말할 수 없는 것만** — 여러 테이블을 가로지르는 조합, 없는 데이터의 경계 | 스키마를 되풀이하면 두 곳이 어긋나고, 어긋난 쪽을 아무도 모른다 |
| `CLAUDE.md` | "국회 질문은 이 스킬로" 세 줄 | 매 세션 로드된다. 이 프로젝트에서 **모든** 세션이 알아야 하는 건 라우팅 하나뿐이다 |
| 코드 (argparse·CHECK·FK) | 어겨지면 안 되는 것 | 프로즈는 지켜지길 바라는 것이고 코드는 지켜지는 것이다 |

**`References/`를 만들지 않았다.** 어휘는 `SELECT DISTINCT`가, 허용값은 `CHECK`가, 관계는 FK가 답한다. 그걸로 안 되는 조합 레시피가 실제로 나왔을 때 그때 만든다.

## Component specs

### `.claude/skills/congress/` — 유일한 스킬

`allowed-tools`가 `Bash(uv run:*)` · `Bash(sqlite3:*)` · `Read` · `Glob` · `Grep`이다. 쓰기 도구가 없다 — 조회가 목적이고, 수집은 `collect.py` 하나가 오케스트레이션한다.

`Scripts/`의 일곱 파일은 **층이 아니라 도메인으로 잘랐다.** `parsers.py`/`collect.py`로 나누면 국회가 의안 상세 DOM을 바꿀 때 두 파일을 고쳐야 한다 — 함께 바뀌는 것이 갈라져 있는 배치다. 도메인(`bills` · `members` · `meetings`)으로 자르면 한 변경이 한 파일에 갇히고, 도메인을 가로지르는 공통 관심사(`net` · `db` · `audit`)만 따로 뺐다.

진단 도구가 **둘**인 것이 이 스킬의 특징이다. 둘은 다른 질문에 답한다.

```
db.py selftest   우리 코드가 회귀했나      네트워크 없음 · 임시 DB
verify.py        국회 사이트가 바뀌었나    네트워크 있음 · DB 없음
```

수집이 조용히 빈손으로 오기 시작할 때 어느 쪽이 깨졌는지를 이 둘이 가른다. 하나만 있으면 매번 파서부터 뜯게 된다.

> ⚠️ **`selftest`는 첫 동작이 대상 DB 삭제다.** 그래서 `--db`를 **필수 인자로** 만들고 실제 `CONGRESS.db`를 지목하면 argparse가 거부한다. 경고 문구가 아니라 인자 자체를 필수로 둔 이유는 News 프로젝트에서 그렇게 4.25GB를 잃었기 때문이다 — 이름이 selftest라 안전할 것이라고 넘겨짚고 사용법을 읽지 않은 것이 전부였다.

### `CLAUDE.md` — 세 줄

컴포넌트를 **나열하지 않는다.** 스킬 목록은 자동으로 뜨고, 손으로 적은 목록은 곧 실제와 어긋난다. 여기 있는 건 라우팅 하나와 "수집은 자동으로 도니 질문마다 다시 돌리지 마라" 한 줄이다.

사용자 스코프의 `~/.claude/CLAUDE.md`와 **합쳐져** 로드된다(덮어쓰기가 아니다). 그쪽은 git 작업 흐름·마크다운 규칙·질문 방식을 담고 이쪽은 도메인 라우팅만 담아서 겹치지 않는다.

### `.github/workflows/` — 두 워크플로

이건 `.claude/workflows/`가 아니라 GitHub Actions다. 클로드가 부르는 오케스트레이션이 아니라 **사람 없이 도는 크론**이라 층이 다르다.

> ⚠️ **DB를 체크아웃 안에 두지 마라.** `actions/checkout`은 기본으로 `git clean -ffdx`를 도는데 `-x`가 **gitignore된 파일까지 지운다.** 작업공간에 DB를 두면 매 실행 첫 스텝이 수집물을 통째로 날리고, 에러는 나지 않는다. 그래서 `CONGRESS_DB`가 작업공간 밖 실제 경로를 겨눈다 — 체크아웃은 코드 운반체일 뿐이다.

> ⚠️ **판정 결과를 파이프로 넘기지 마라.** `collect.py | tee`는 셸이 마지막 명령의 종료코드를 돌려주므로 게이트 위반의 1이 `tee`의 0으로 덮인다. 게이트·불변조건·빨간불이라는 설계 전체가 그 한 줄에서 무력해진다.

러너는 `~/actions-runner-congress-api` (`congress-api-seongjin-mac`)다. **`~/actions-runner-congress`는 이 저장소가 아니다** — 지금도 살아 도는 `Congress-DB` 소속이니 건드리지 마라.

## Validation scenarios

새 세션에서 이걸 물어 확인한다. 답이 맞는지보다 **스킬이 뜨는지와 스스로 SQL을 조립하는지**를 본다.

| 물어볼 것 | 통과 기준 | 최근 확인 |
|---|---|---|
| "이해민 의원이 발의한 법안 중 계류 중인 것" | 스킬이 뜨고 `.schema`를 읽어 SQL을 조립한다. 690건·대표발의 56건 | 2026-08-09 통과 |
| "이 법안 표결에서 기권한 의원" | **불참과 기권을 혼동하지 않는다.** 명단은 기권만 주고 불참은 재적−재석으로 계산한다 | 2026-08-09 통과 |
| 아무 국회 질문이나 | WebSearch·OpenAPI로 새지 않는다 | 2026-08-09 통과 |

기계적 확인은 셋이 나눠 맡는다.

```bash
uv run .claude/skills/congress/Scripts/db.py selftest --db /tmp/t.db   # 우리 코드
uv run .claude/skills/congress/Scripts/verify.py                       # 국회 사이트
uv run .claude/skills/congress/Scripts/audit.py --db …                 # 적재된 데이터
```

## Change history

### 2026-08-09 — 스펙 최초 작성 (sync)

**이 스펙은 하네스보다 늦게 만들어졌다.** 스킬·CLAUDE.md·워크플로가 먼저 있었고 이 문서가 디스크를 읽어 복원한 것이라, 여기 적힌 근거는 사후 재구성이지 설계 시점의 기록이 아니다. 다음 패스부터가 진짜 이력이다.

같은 날 구현 세션이 계획 문서의 서술 여섯 개를 실측으로 반증했다(PR #12·#14~#25). 하네스에 직접 닿는 것만 옮겨 적는다.

- 러너: 계획은 `Congress-DB`를 폐기했다고 적었으나 살아 있다. 지시대로 러너를 가져왔으면 남의 일일 파이프라인을 멈출 뻔했다.
- 워크플로: 체크아웃이 DB를 지우고 파이프가 종료코드를 삼키고 있었다. 셋 다 실행해 보기 전에는 초록불로 보인다.
- 감사: 원천이 보장하지 않는 것을 게이트로 걸고 있던 셋(`sitting_gaps` · `promulgated_without_number` · `dangling_alt_bills`)을 보고값으로 내렸다. 고칠 수 없는 빨간불은 표 전체를 무시하게 만든다.

**B5–B7의 근거** — 다음 패스가 판단할 재료다.

- **B5(훅)**: 이 세션에서 `Scripts/*.py`를 열 번 넘게 고치며 `selftest`를 손으로 돌렸다. 그런데도 `bill_kind` 회귀는 세 시간 뒤에야 잡혔고, 그 사이 `bill_detail_missing` 게이트가 **아무것도 검사하지 않으면서 초록불**이었다. 편집 시점에 자동으로 돌았으면 그 자리에서 빨간불이었다.
- **B6(permissions)**: `settings.json`이 없어 `uv run`·`sqlite3`·`gh`가 매번 프롬프트를 탄다. 프롬프트를 줄이지만 안전을 더하지는 않는다.
- **B7(rule)**: 파서 작성의 교훈(이 도메인의 실패는 200 OK에 빈 결과다 · `<i>` 라벨을 먼저 지워라 · 열 위치 대신 `class`로 읽어라)이 지금은 코드 주석에 흩어져 있다. 다만 스키마 주석과 겹칠 소지가 있어 보류했다.
