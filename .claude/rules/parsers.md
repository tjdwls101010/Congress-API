# 국회 원천을 긁는 코드를 쓸 때

**이 도메인의 실패는 예외가 아니라 200 OK에 빈 결과다.** 국회 사이트는 폼이 틀려도, 값이 없어도, 파싱이 어긋나도 에러를 주지 않는다. 그래서 아래 규칙은 대부분 "성공처럼 보이는 실패"를 잡는 것이고, 공통 처방은 하나다 — **파싱 결과가 비면 성공으로 넘기지 말고 실패로 기록해라.** 넘기면 그 0건이 그대로 답이 된다.

## 원천에 요청할 때

**폼 전체를 보내라.** 파라미터를 빼면 400이 오고, 우리 코드는 그걸 "원천이 값을 안 준다"로 읽는다. `voteInfo.do`에 `{billId, _csrf}`만 보내면 12바이트짜리 `Bad Request.`가 오지만, 바로 앞 `billInfo.do` 호출이 이미 만들어 둔 폼을 그대로 `{**f, "_csrf": …}`로 보내면 145KB에 `voteAgreeList`가 들어 있다. 수정가결 22건의 표결이 "원천이 안 준다"로 오진돼 있던 원인이 이것이다.

**JSON을 주는 엔드포인트가 있는지 먼저 확인해라.** HTML에서 유도하려던 값을 원천이 직접 말해 주는 경우가 있다 — `findBillDetail.do`는 476바이트에 현재 소관위·제안일·처리일·처리결과·정부이송일·공포일·발의자 문자열을 전부 담아 준다. HTML 파싱은 DOM이 바뀌면 깨지지만 JSON 필드는 안 깨진다.

**페이징하는 팝업은 총원을 스스로 선언한다.** 발의자 목록은 한 번에 14명까지만 오고, 같은 응답이 `pager_count_text`(예: `191`)와 `pager_pages_text`(예: `" (1/14 페이지)"`)로 전체를 알려 준다. 이걸 안 읽으면 191명짜리 의안에서 14명만 가져오고도 성공으로 보인다.

> ⚠️ **`page`가 마지막을 넘으면 에러가 아니라 마지막 페이지를 다시 준다.** 빈 응답을 종료 조건으로 쓰면 무한 루프다. 페이지 수는 반드시 선언된 값에서 계산해라.

## HTML을 읽을 때

**표는 caption으로 찾고 값은 `<td class>`로 읽어라 — 열 위치로 읽지 마라.** 원천이 처리현황에 따라 칸을 넣고 뺀다. 관련위 표에는 처리결과 칸이 아예 없다. 열 번호로 읽는 코드는 그 표에서 조용히 옆 칸을 가져온다.

**캡션이 값을 담을 때가 있다.** 체계자구 표에는 위원회 칸이 없고, caption의 `법사위 체계자구 심사정보`가 곧 그 값이다. 칸이 없다고 값이 없는 게 아니다.

**칸이 있는데 원천이 비워 보내는 경우와, 우리가 못 읽는 경우를 구별해라.** 관련위 의견서제시일은 class(`procDt`)도 있고 매핑도 되어 있지만 라벨 `<i>`만 오고 값 `<span>`이 없다. 이 둘을 안 가르면 멀쩡한 파서를 뜯게 된다 — 원천의 응답 원문을 먼저 확인해라.

**이 원천은 값 주위에 공백과 개행을 대량으로 넣는다.** 그래서 `<dd>` 값에 `re.match`를 쓰면 맨 앞 매칭이 매번 실패하고(`re.search`를 써라), `text()`에서 `strip=True`를 빼면 값이 공백 덩어리가 된다. 실제로 의원 162명의 당선횟수가 잘렸고, 조국 의원의 `district`가 181자 공백이 됐다.

**정규식 대안(`|`)은 앞쪽에서 먼저 맞는 것이 이긴다 — catch-all을 넣지 마라.** party 폴백의 `[가-힣]{2,10}당`이 "국회의사당"을 물어 의원 5명의 소속이 `'의사당'`이 됐다. 정당명을 대안 앞쪽에 나열해도 안 막힌다. 문자열의 더 앞에서 맞는 catch-all이 언제나 이기기 때문이다.

**중점은 두 종류다.** `ㆍ`(U+318D)와 `·`(U+00B7)가 섞여 온다. 텍스트 진입점 한 곳에서 `·`로 정규화해라 — 안 하면 같은 이름이 두 값이 된다.

## 셀 때와 DB에 쓸 때

**`expected`를 자기 자신의 길이로 주지 마라.** `replace_children(…, expected=len(rows))`는 항상 참이라 검사가 아니다. **발의자 34,270명이 그렇게 사라졌고, 표결도 지금 같은 모양이다.** 개수는 반드시 **같은 응답 안의 독립적인 출처**에서 와라 — 팝업의 `pager_count_text`, JSON의 `proposerInfo`.

> 제목의 `등 N인`은 쓰지 마라. `외 N인` 44건과 위원장·정부 발의 1,654건에서 깨진다. 원천이 스스로 선언한 총원이 제목 파싱 변종에 면역이다.

**UPSERT의 `DO UPDATE SET`에 새 컬럼을 빠뜨리지 마라.** `meetings.session_kind`가 빠져 모순된 행 20개가 생겼고, `--force` 재수집으로도 안 고쳐졌다 — 갱신 경로에 없는 컬럼은 첫 삽입 값에 영원히 고정된다.

**성공하면 하위 실패를 반드시 지워라.** `clear_failure`를 안 부르면 고친 뒤에도 게이트가 영구히 빨갛고, 그러면 사람이 게이트 표 전체를 안 믿게 된다. 고칠 수 없는 빨간불은 아무것도 안 지키는 것보다 나쁘다.

**삼항연산자는 `or`보다 우선순위가 낮다.** `A or B if C else ""`는 `(A or B) if C else ""`로 묶인다. 이 코드베이스에서 실제로 발언 텍스트가 통째로 빌 뻔했다.
