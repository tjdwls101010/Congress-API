# 05 — 문서 개정

`SKILL.md` · `readme.md` · `harness-spec.md` · 스키마 주석에서 **실측과 어긋나는 서술**을 전부 찾아 고친다.

문서의 틀린 수치는 단순한 오타가 아니다. **다음 세션이 그 수치를 믿고 SQL을 짜면 조용히 틀린 답이 나온다.** 특히 SKILL.md의 통과 판정식은 지금 그대로 쓰면 실제로 통과한 법안 하나를 놓친다.

## SKILL.md — 틀린 것

### ① 통과 판정식이 법안 1건을 놓친다 ★

지금 SKILL.md에 이렇게 적혀 있다.

```sql
decision_result IN ('원안가결','수정가결')
  AND (reconsideration_result IS NULL OR reconsideration_result = '가결')
```

```sql
SELECT reconsideration_result, COUNT(*) FROM bills GROUP BY 1;
-- NULL 20571 · '부결' 26 · '원안가결' 1
```

**`'가결'`이라는 값이 실제로는 존재하지 않는다.** `2200851`(방송법, 김현의원 등 17인)만 `'원안가결'`로 저장돼 있어 두 조건 모두 거짓이 되고, 재의결까지 통과한 이 법이 "미통과"로 나온다.

**v2에서는 이 문장 전체가 사라진다.** `decision_result`와 `reconsideration_result`가 둘 다 삭제되고 `outcome='공포'` 한 줄로 대체된다.

### ② 틀린 수치 둘

| 지금 | 실측 | 질의 |
|---|---|---|
| "가결 법안의 **64%**가 사라진다" | **67.0%** (1,826건 중 1,224건) | `decision_result IN ('원안가결','수정가결')`인 의안 중 `bill_proposers`에 행이 없는 비율 |
| "화자의 **42%**가 의원이 아니다" | **37.3%** (40,573명 중 15,120명) | `meeting_speakers`의 `open_na_id IS NULL` 비율 |

42%는 회의 1건 표본(105블록 중 44개)을 전체로 일반화한 값으로 보인다. **표본으로 잰 값을 전수로 적으면 안 된다** — 다음 세션이 그 수치를 근거로 판단한다.

### ③ 사라지거나 바뀌는 함정 서술

v2 스키마가 컬럼으로 해결하므로 SKILL.md에서 **삭제**한다.

| 지금의 함정 | v2에서 |
|---|---|
| 통과 판정에 `decision_result`만 쓰면 틀린다 | `outcome='공포'` — 함정 소멸 |
| 대안반영폐기가 위원회 단계에만 적혀 500건 가까이 놓친다 | `outcome='대안반영폐기'` — 함정 소멸 |
| 재의 결과를 함께 봐야 한다 | `outcome='재의부결'` — 함정 소멸 |
| `bill_votes`에 행이 없는 것은 불참이 아니다 | `bill_vote_summary.absent` 생성 컬럼 — 함정 소멸 |
| 소위원회 이름은 `상위 + 공백 + 소위명` | 스키마 주석과 `parent_committee` FK가 이미 답한다 — 스키마로 이동 |

**남는 셋** — 조인의 성질이라 컬럼으로 표현할 수 없다. SKILL.md에 유지한다.

- `bill_proposers`만 조인하면 가결 법안의 **67%**가 사라진다 (위원장 대안 934 · 정부제출 601)
- `bill_stages`는 언제나 LEFT JOIN
- 안건과 발언을 잇지 마라

### ④ 새로 적어야 할 것

| 내용 | 왜 |
|---|---|
| **`bills.title`의 중점은 `·`로 정규화돼 있다** | 원천은 `ㆍ`를 섞어 쓰는데 우리는 통일했다. 원천 화면과 대조할 때 다를 수 있다 |
| **공포된 법의 이름은 `bill_promulgated_laws`에 있다** | 의안명과 다른 것이 53건. `인구전략기본법`·`평생교육법` 등은 `title` 검색으로 못 찾는다 |
| **일괄개정법률안은 한 의안이 법률 여러 개를 공포한다** | 53건. 법률 수를 세려면 `bill_promulgated_laws`를 세야 한다 |
| **`outcome`이 결말의 단일 정본이다** | 컬럼 하나로 끝난다는 것을 명시해야 클로드가 옛 방식으로 조합하지 않는다 |
| **`district IS NULL`이 비례대표다** | 46명 |
| **`LIKE`는 인덱스를 안 탄다** | `idx_bills_title`은 접두 LIKE에도 안 쓰인다. 20,598행이라 스캔이 싸다는 것을 함께 적어 불안을 없앤다 |

## readme.md — 틀린 것

### "법률안만 상세를 받는다"가 사실이 아니다

```sql
SELECT bill_kind, COUNT(*), SUM(detail_collected_at IS NOT NULL) FROM bills GROUP BY 1;
-- 법률안 19985/19985 · 결의안 220/220 · 기타 88/88 · 동의안 74/74 · 예산안 59/59 · …
```

**20,598건 전부가 상세를 받았다.** 목록이 `bill_kind`를 주지 않아 `'미상'`으로 넣고 상세에서 확정하는 구조라 그렇다 — **모든 의안이 최소 1회 상세를 거친다.**

readme의 "그중 **법률안**만 상세·표결·발의자·심사단계"는 **발의자에만 해당한다.** 심사단계·표결은 비법률안에도 들어온다.

readme와 스키마 주석 양쪽을 실제 동작에 맞춰 고친다.

> **`20,510`은 틀리지 않았다.** 숫자 의안번호가 정확히 20,510건이고(2200001–2220510, 구멍 0) `ZZ22124` 형식 88건을 더해 20,598이다. 이 수치는 그대로 둔다.

### `meetings` 행 불변조건과 어긋나는 서술

readme의 "열거 2,056 / 수집 2,047"과 스키마 주석의 "**본문 수집 여부와 무관하게 행이 생긴다**"가 모순이다. 실제로는 본문 수집에 실패하면 트랜잭션이 통째로 롤백돼 `meetings`에 행조차 없다([01번 F2](01-진단.md)).

[03번](03-갱신-설계.md)의 스텁 선행 커밋이 들어가면 **주석대로 동작하게 되므로** 그때 readme를 실제에 맞춘다. 순서가 중요하다 — 코드를 고치기 전에 문서를 고치면 또 어긋난다.

## 스키마 주석 — 틀린 것

| 위치 | 지금 | 실측 |
|---|---|---|
| `bills.detail_collected_at` | "비법률안은 영원히 NULL이고 그게 정상이다" | **전 의안이 non-NULL.** 모든 의안이 상세를 거친다 |
| `bills.proposer_kind` | `'의원' \| '위원장' \| '정부'` | **다섯이다.** `'의장'` 56건 · `'기타'` 63건 |
| `bill_stages.committee_name` | "소관위·소위·관련위·**체계자구** 단계의 위원회" | 체계자구는 원천에 칸이 없다. 상수로 채운다 |
| `bill_vote_summary.result` | `'원안가결' \| '수정가결' \| '부결'` | 코드상 채워질 수 없었다(리터럴 `None`) |
| `members.district` | "비례대표는 NULL" | 46건이 문자열 `'비례대표'`, 1건은 181자 |
| `members.mona_cd` | "NULL이 정상인 행이 두 종류" | v2에서 컬럼 삭제 |
| `meetings` | "본문 수집 여부와 무관하게 행이 생긴다" | 실패 시 행조차 없다 |
| `meetings.session_no` | "국정감사(317건)만 NULL이 정상" | **330건이다.** 상임위 11 · 특위 1 · 국정조사 1이 더 있다 |
| `collect_failures` | `MAX_ATTEMPTS`를 "넘으면 큐에서 빠진다" | 회의록은 안 빠진다. 감사에서만 사라진다 |

**`members.office_phone`·`email`은 "전직만 NULL"이 아니다.** 현직 중에도 전화 1명·이메일 6명이 NULL이다. `office_room`·`homepage`는 주장대로 전직 21명만 NULL이다 — 넷을 한 묶음으로 적은 주석을 나눈다.

## harness-spec.md

- **"`Scripts/`의 일곱 파일"** — 실제로는 8개다(`collect.py` 포함). 세는 대상을 명확히 하거나 수를 지운다.
- **Behavior inventory의 B5~B7을 `proposed` → `validated`로** 옮긴다([06번](06-하네스-층.md)에서 전부 구현하기로 했다).
- **Component specs에 `bill_promulgated_laws` 신설과 `outcome` 도입의 근거를 남긴다.** 특히 "왜 뷰가 아니라 컬럼인가"는 다음 패스가 다시 고민할 자리다.
- **Change history에 이 세션을 기록한다** — v1이 실측으로 반증된 항목과, 그 근거가 된 원천 실측(2026-08-09).

## 문서 사이의 역할 경계를 다시 지킨다

v1의 원칙은 옳았다. **스키마가 말할 수 있는 것을 SKILL.md가 되풀이하지 않는다.** 이번 개정으로 그 경계가 다시 그어진다.

| 두는 곳 | 담는 것 |
|---|---|
| 스키마 주석 | 컬럼의 의미와 함정. `outcome` 유도 순서, 중점 정규화, 비례대표 NULL 규약 |
| `SKILL.md` | **여러 테이블을 가로지르는 것만** — 조인 함정 3개, 데이터 경계, 도구 사용법 |
| `CLAUDE.md` | 라우팅 세 줄. 그대로 둔다 |
| `readme.md` | 사람이 프로젝트를 이해하는 문서. 적재 실적과 왜 만드는가 |
| `harness-spec.md` | **판단의 기록.** 무엇을 왜 그 층에 두었나 |

**SKILL.md는 이번 개정으로 짧아진다.** 함정 5개가 스키마로 내려가기 때문이다. 짧아진 만큼 남은 셋이 더 잘 보인다.
