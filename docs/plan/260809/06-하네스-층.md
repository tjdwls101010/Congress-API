# 06 — 하네스 층 (B5 · B6 · B7)

`harness-spec.md`에 `proposed`로 보류돼 있던 셋을 전부 구현한다. 보류의 근거는 2026-08-09 세션이 남겼고, 이번 개편이 **파서를 대폭 고치는 작업**이라 그 근거가 더 강해졌다.

## B5 — `Scripts/*.py` 편집 시 `selftest` 자동 실행

### 근거

지난 세션의 기록: `Scripts/*.py`를 열 번 넘게 고치며 `selftest`를 손으로 돌렸는데도 `bill_kind` 회귀가 **세 시간 뒤에야** 잡혔고, 그 사이 `bill_detail_missing` 게이트는 **아무것도 검사하지 않으면서 초록불**이었다.

이번 개편은 그때보다 파서를 훨씬 많이 고친다 — `bills.py`·`members.py`·`meetings.py` 셋 다, 그리고 스키마가 통째로 바뀐다. **같은 일이 더 쉽게 난다.**

### 비용은 사실상 0이다

```
$ time uv run .claude/skills/congress/Scripts/db.py selftest --db <임시경로>
전부 통과
0.156 total
```

**0.156초.** 디바운스도 배치도 필요 없다. 매 편집마다 돌려도 사람이 느끼지 못한다.

### 설계

`PostToolUse`에 건다. 편집을 **막을** 필요가 없고(막을 수도 없다 — 이 이벤트는 도구가 이미 성공한 뒤에 뜬다) 회귀를 **즉시 알리는** 것이 목적이기 때문이다.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command", "command": ".claude/hooks/selftest-on-parser-edit.sh" }
        ]
      }
    ]
  }
}
```

훅 스크립트가 하는 일:

1. stdin의 JSON에서 `tool_input.file_path`를 읽는다.
2. 그 경로가 `.claude/skills/congress/Scripts/` 아래의 `.py`가 아니면 **조용히 exit 0.**
3. 맞으면 `db.py selftest --db "$(mktemp -u)/selftest.db"`를 돌린다.
4. **통과하면 아무것도 출력하지 않는다.** 실패하면 exit 2 + stderr로 실패한 케이스를 보여준다.

> **성공 시 침묵이 핵심이다.** 편집마다 "전부 통과"를 출력하면 40번의 편집이 40줄의 노이즈가 되고, 그러면 41번째의 진짜 실패가 묻힌다. 훅은 말할 것이 있을 때만 말한다.

### 안전

⚠️ **훅이 `--db`에 실제 `CONGRESS.db`를 넘기는 일이 절대 없어야 한다.** `selftest`의 첫 동작이 대상 파일 삭제다.

두 겹으로 막는다. ⓐ 훅 스크립트가 `mktemp`로 만든 경로만 넘긴다. ⓑ `db.py`의 argparse 가드가 실제 DB 경로를 지목하면 거부한다(이미 있다). **가드를 훅 때문에 완화하지 마라** — News 프로젝트에서 4.25GB를 잃은 것이 그 가드가 생긴 이유다.

### 검증

훅은 `validate_harness.py`가 검사하지 못한다. **반드시 `test_hook.py`로 확인한다.**

```bash
python3 ~/.claude/skills/harness-creator/scripts/test_hook.py \
  --settings .claude/settings.json --event PostToolUse --tool Edit \
  --input-field 'tool_input.file_path=.claude/skills/congress/Scripts/bills.py'
```

`Scripts/` 밖의 경로로도 한 번 돌려 **조용히 통과하는지** 확인한다 — 매처가 `Write|Edit` 전체라 필터가 훅 스크립트 안에 있고, 그 필터가 이 훅의 유일한 정확성 보장이다.

## B6 — 읽기 전용 명령 허용

### 근거와 한계

`settings.json`이 없어 `uv run`·`sqlite3`·`gh`가 매번 프롬프트를 탄다. **이건 편의이지 안전이 아니다** — 지난 세션의 판단이 옳았고, 그 판단을 그대로 유지한다. 편의만 주는 변경이므로 범위를 좁게 잡는다.

### 허용

**명령 이름이 아니라 경로까지 박아서** 허용한다. `Bash(uv run:*)`처럼 넓게 열면 `uv run`으로 무엇이든 실행할 수 있어 의미가 없다.

```json
{
  "permissions": {
    "allow": [
      "Bash(uv run .claude/skills/congress/Scripts/audit.py:*)",
      "Bash(uv run .claude/skills/congress/Scripts/verify.py:*)",
      "Bash(uv run .claude/skills/congress/Scripts/collect.py --audit-only:*)",
      "Bash(uv run .claude/skills/congress/Scripts/db.py schema:*)",
      "Bash(gh run list:*)",
      "Bash(gh pr list:*)",
      "Bash(gh pr view:*)"
    ]
  }
}
```

**`sqlite3`는 허용 목록에 넣지 않는다.** 같은 명령으로 `DROP TABLE`도 되고, 하위 명령으로 읽기와 쓰기를 가를 방법이 없다. 조회는 스킬의 `allowed-tools`가 이미 담당하므로 잃는 것도 없다.

**`selftest`도 넣지 않는다.** 대상 DB를 지우는 명령이 프롬프트 없이 도는 것은 편의로 살 값이 아니다. B5의 훅이 자동으로 돌려 주므로 손으로 칠 일도 줄어든다.

### 거부

```json
    "deny": [
      "Bash(rm:*CONGRESS.db*)",
      "Bash(git clean:*)"
    ]
```

둘 다 이 프로젝트에서 실제로 데이터를 날린 적이 있는 모양이다 — `git clean -ffdx`가 gitignore된 DB를 지우는 것이 GitHub Actions 워크플로의 알려진 함정이고(`harness-spec.md`), `rm`은 설명이 필요 없다.

> ⚠️ **`deny` 패턴은 문자열 매칭이라 우회가 쉽다.** 이건 실수를 막는 난간이지 방벽이 아니다. 진짜 보호는 DB를 작업공간 밖에 두는 것(이미 그렇게 하고 있다)과 argparse 가드다.

## B7 — 파서 작성 규칙을 `Scripts/**`에서만 로드

### 보류 이유였던 "스키마 주석과 겹친다"에 대한 답

겹치지 않는다. **독자와 시점이 다르다.**

| | 스키마 주석 | `.claude/rules/parsers.md` |
|---|---|---|
| 언제 읽히나 | `.schema`를 부를 때 = **조회할 때** | `Scripts/*.py`를 열 때 = **코드를 쓸 때** |
| 담는 것 | 이 값이 무엇이고 어떻게 조인하나 | 이 원천을 어떻게 긁어야 안 깨지나 |
| 예 | "체계자구 단계는 언제나 법사위다" | "`re.match`를 쓰지 마라 — `<dd>`가 개행으로 시작한다" |

조회하는 클로드는 `re.match` 함정을 알 필요가 없고, 파서를 쓰는 클로드는 그것만 알면 된다. **지금은 이 교훈이 코드 주석에 흩어져 있어 새 파서를 쓸 때 발견되지 않는다.**

### 설계

```markdown
---
paths:
  - .claude/skills/congress/Scripts/**/*.py
---
```

**`paths:` 프론트매터가 없으면 이 파일은 CLAUDE.md와 똑같이 매 세션 로드된다.** 그러면 `rules/`로 나눈 의미가 통째로 없어진다.

⚠️ `paths:`가 붙은 규칙은 **컴팩션 후 다시 주입되지 않는다** — 그 디렉터리의 파일을 다시 읽을 때까지 사라져 있다. 파서를 오래 고치는 세션에서 이 규칙이 중간에 없어질 수 있다는 뜻이다. 그래도 여기 두는 것이 맞다 — 이 교훈들의 최악은 "조금 뒤에 다시 알게 됨"이지 "돌이킬 수 없는 손해"가 아니고, 매 세션 CLAUDE.md 예산을 쓸 값은 아니다.

### 담을 내용

이번 조사에서 **실제로 데이터를 잃게 만든 것들만** 담는다. 일반적인 파이썬 조언은 넣지 않는다.

| 규칙 | 왜 (이 프로젝트에서 실제로 난 일) |
|---|---|
| **이 도메인의 실패는 200 OK에 빈 결과다** | 예외가 안 나고 0건이 그대로 답이 된다. 파싱 결과가 비면 성공으로 넘기지 말고 실패로 기록해라 |
| **`expected`를 자기 자신의 길이로 주지 마라** | `replace_children(…, expected=len(rows))`가 항상 참이 되어 **발의자 34,270명이 사라졌다.** 개수는 반드시 독립적인 출처(제목의 `등 N인`)에서 와라 |
| **`re.match` 대신 `re.search`** | 원천의 `<dd>`가 개행·탭으로 시작해 맨 앞 매칭이 매번 실패한다. 의원 162명의 당선횟수가 잘렸다 |
| **`text()`에 `strip=True`를 빼지 마라** | 조국 의원 `district`가 181자 공백 덩어리가 됐다 |
| **중점은 두 종류다** | `ㆍ`(U+318D)와 `·`(U+00B7). 진입점에서 `·`로 정규화한다 |
| **열 위치 대신 `class`로 읽어라** | 원천이 칸을 추가·제거한다. 관련위 표에는 처리결과 칸이 아예 없다 |
| **캡션이 값을 담을 때가 있다** | 체계자구 표에는 위원회 칸이 없고 캡션 `법사위 체계자구 심사정보`가 그 값이다 |
| **UPSERT의 `DO UPDATE SET`에 새 컬럼을 빠뜨리지 마라** | `meetings.session_kind`가 빠져 모순 행 20개가 생겼고 `--force` 재수집으로도 안 고쳐졌다 |
| **하위 실패는 성공 시 반드시 지워라** | `clear_failure`를 안 부르면 고쳐도 게이트가 영구히 빨갛고, 그러면 사람이 게이트 전체를 안 믿는다 |
| **삼항연산자는 `or`보다 우선순위가 낮다** | `A or B if C else ""` 가 `(A or B) if C else ""` 로 묶여 발언이 통째로 빌 뻔했다 |

## CLAUDE.md는 그대로 둔다

지금 세 줄이고, 그 셋이 **모든 세션이 알아야 하는 것**이다. B5~B7 중 어느 것도 여기 이름을 올리지 않는다 — 훅·규칙·permissions는 자동으로 작동하고, 컴포넌트 목록을 손으로 적으면 곧 실제와 어긋난다.

한 줄만 검토한다: **훅이 차단하듯 보일 때 그 이유를 설명하는 줄이 필요한가?** B5는 차단하지 않고(PostToolUse는 막을 수 없다) 실패 시에만 말하므로, 그 출력 자체가 이유를 설명한다. **필요 없다.**

## 구현 순서 주의

⚠️ **`.claude/` 아래 첫 쓰기는 보호된 경로라 권한 프롬프트가 뜬다.** `dontAsk` 모드에서는 거부되고, 어떤 allow 규칙으로도 미리 승인할 수 없다. 구현 세션은 이걸 미리 알고 시작해야 한다.

세 개를 만든 뒤 반드시:

```bash
python3 ~/.claude/skills/harness-creator/scripts/validate_harness.py --path .    # 오류 0
python3 ~/.claude/skills/harness-creator/scripts/test_hook.py --settings … --event PostToolUse …
```

`validate_harness.py`는 훅이 실제로 도는지 확인하지 못한다. **`test_hook.py`가 통과하기 전에는 B5가 완성된 것이 아니다.**
