# congress 스킬 v2 개선 계획 — 2026-08-09

`congress` 스킬 v1을 실측으로 점검하고, 그 결과를 바탕으로 v2 스키마·수집기·문서를 다시 설계한 계획이다. **이 세션은 계획만 세웠고 코드는 한 줄도 고치지 않았다.** 구현은 다음 세션이 이 문서를 읽고 한다.

## 왜 v2인가

v1은 동작한다. 의안 20,598건·회의록 2,047건·발언 140만 행이 들어와 있고 의안번호에 구멍이 0이다. **문제는 채워지지 않은 것과, 앞으로 채워지지 않을 것이다.**

- `bills.committee_name`이 20,598건 **전부 NULL**이다. 같은 값이 `bill_stages`에는 100% 있다.
- `bill_stages.doc_url`이 51,776행 **전부 NULL**이고, 이 컬럼을 채우는 코드가 저장소 어디에도 없다.
- `members`의 `sex`·`mona_cd`·`elect_kind`·`profile_text`가 320명 **전부 NULL**이고, `term_count`는 `재선(제21대,` 처럼 잘려 있다.
- **상세는 한 번 받으면 영영 다시 받지 않는다.** 계류 중인 14,780건의 심사단계가 앞으로 영원히 낡는다.

마지막 것이 가장 크다. 지금 전체가 멀쩡해 보이는 이유는 2026-08에 DB를 통째로 다시 만들었기 때문이지 갱신이 작동해서가 아니다.

## 이 계획을 관통하는 원칙

**① NULL 비율은 결함의 지표가 아니다.**

`promulgated_law_name`이 93% NULL인 것은 정상이다 — 공포된 법이 7%뿐이기 때문이다. 공포 단계가 있는 1,475건 중 1,471건이 채워져 있으니 이 컬럼은 만점이다. 반대로 `committee_name`은 100% 채워져야 하는데 0%다. **봐야 할 것은 "채워져야 할 행에서 채워졌는가"이지 전체 NULL 비율이 아니다.**

**② 선언만 되고 영원히 빈 컬럼이 가장 나쁘다.**

클로드는 스키마를 읽고 "이 컬럼에 값이 있을 수 있다"고 가정해 SQL을 짠다. 그 컬럼이 항상 NULL이면 **에러 없이 0건**이 나오고, 0건은 실패처럼 보이지 않아 그대로 답이 된다. 그래서 빈 칸은 셋 중 하나로 결론나야 한다 — **채우거나, 지우거나, "원천이 안 준다"고 주석에 못 박거나.** 어중간하게 남겨 두는 선택지는 없다.

**③ 컬럼 하나는 클로드가 한 번 더 들여다보는 비용이다.**

그래서 유도 가능한 것은 지운다. 다만 "유도 가능"은 실측으로 증명해야 한다 — `promulgated_law_name`은 96%가 제목에서 유도되지만 나머지 4%(53건)가 하필 가장 중요한 법들이라 지울 수 없었다(저출산·고령사회기본법 → **인구전략기본법**).

**④ 이력은 행으로, 현재는 컬럼으로.**

`bill_stages`는 사건 원장이고 `bills`의 상태 컬럼은 그 원장에서 계산된 현재 상태 투영이다. 둘 다 있는 것이 옳다. 원장은 이력을 지키고 투영은 검색을 빠르게 한다. **v1에 없던 것은 둘이 어긋났을 때 알아채는 장치뿐이다.**

> SQLite에서 UPDATE는 INSERT와 비용이 같다. PK 인덱스를 타서 한 행을 제자리에서 고치고 파일 전체를 다시 쓰지 않는다. 테이블을 나누는 이유는 수정 비용이 아니라 **이력이 사라지는 것**이다.

## 이 세션에서 합의된 결정

| 주제 | 결정 |
|---|---|
| DB 재구축 | **전면 재수집 OK.** 마이그레이션 스크립트를 쓰지 않고 스키마를 자유롭게 고친다 |
| `decision_result` | **삭제.** `bill_stages`(본회의)가 20,597/20,598 동일하게 갖고 있다 |

| `committee_name` | `current_committee`로 이름을 바꿔 유도 컬럼으로 되살린다 |
| `head_memo` · `status_memo` | **둘 다 삭제** |
| `promulgated_law_name` | 삭제하고 `bill_promulgated_laws` 테이블로 (일괄개정법률안 53건 때문) |
| `proposer_summary` | 삭제. 의원발의는 `bill_proposers`가, 그 밖은 `proposer_org`가 담는다 |
| `proposal_session` | INTEGER로 (`제22대(2024~2028)제418회` → `418`) |
| 텍스트 정규화 | **중점 `ㆍ`(U+318D) → `·`(U+00B7) 하나만.** 다른 변종은 실측 결과 0건 |
| 갱신 | **변경 감지 + 주기 강제** |
| 일괄개정 | 공포 행을 1개로 접고 법률명은 별도 테이블 |
| `members` | `sex`·`mona_cd` 삭제, `elect_kind` 신설 안 함(`district`로 갈린다), 약력·역대임기 안 담음 |
| 표결 누락 956표 | 이름으로 매칭해 채운다 (동명이인은 박지원 1쌍뿐) |
| 하네스 층 | **B5 훅 · B6 permissions · B7 rule 전부 이번에 한다** |

## 이 계획이 목표하지 않는 것

**모든 예외를 견디는 시스템을 만들지 않는다.** 목표는 대부분의 상황에서 올바르게 작동하고, 틀렸을 때 조용하지 않은 시스템이다. 그래서 이 계획의 상당 부분이 "고치기"가 아니라 **"원천이 안 주는 것을 주석에 못 박기"**다 — 소위 위원회명 53% 누락은 파서 버그가 아니라 원천이 빈 문자열을 주는 것이고, 그걸 아는 것이 채우려 시도하는 것보다 낫다.
