# 04 — 파서 수정

이 세션에서 **원천 페이지를 실제로 열어 확인한 것**을 먼저 적는다. 추정이 아니라 실측이므로 다음 세션은 이걸 다시 확인하지 말고 그대로 써라 — 단, 국회가 DOM을 바꾸면 무효가 되므로 파서가 안 맞으면 가장 먼저 의심할 것도 여기다.

확인 일자: 2026-08-09. 확인 대상: `2200274`(민주유공자 예우에 관한 법률안) · `2201193`(일괄개정법률안) · 김현 의원 프로필.

## 원천 실측 — 의안 상세 `billDetailPage.do`

캡션이 붙은 표 다섯 개의 실제 헤더다.

| 표 | 헤더 | 우리 스키마와의 차이 |
|---|---|---|
| 소관위 심사정보 | 소관위원회 · 회부일 · 상정일 · 처리일 · 처리결과 · **문서** | 문서 칸은 JS 팝업 링크 |
| 소위 심사정보 | **소위원회** · 회부일 · 상정일 · 처리일 · 처리결과 | **소위원회 칸이 빈 문자열로 오는 경우가 절반** |
| 법사위 체계자구 심사정보 | 회부일 · 상정일 · 처리일 · 처리결과 · 체계자구검토보고서 | **위원회 칸이 아예 없다.** 캡션이 '법사위'라고 말한다 |
| 관련위 심사정보 | 관련위원회 · 회부일 · 상정일 · **의견서제시일** · 문서 | **처리결과 칸이 없다.** 넷째 칸이 '처리일'이 아니라 '의견서제시일' |
| 공포정보 | 공포일자 · 공포번호 · **공포법률** | **법률명이 행마다 다르다** |

이 다섯 줄이 [01번](01-진단.md)의 A4·F7과 [02번](02-스키마-개정.md)의 `bill_stages` 결정을 전부 설명한다.

### 소위 위원회 53% 누락은 파서 버그가 아니다

`2200274`의 소위 심사정보 행:

```json
{"소위원회": "", "회부일": "2024-08-26", "상정일": "", "처리일": "", "처리결과": ""}
```

**원천이 빈 문자열을 준다.** 소위에 회부는 됐지만 어느 소위인지 아직 배정되지 않은 상태다. 채우려 시도하지 말고 스키마 주석에 못 박는다.

⚠️ **소관위 이름을 상속시키지 마라.** "어느 위원회의 소위인가"는 같은 의안의 소관위 단계가 답하므로, 없는 소위 이름을 지어내면 거짓만 늘어난다.

### 체계자구는 상수다

표에 위원회 칸이 없고 캡션이 `법사위 체계자구 심사정보`다. **체계자구심사는 국회법상 법제사법위원회만 수행한다.** 파서가 이 단계 행을 만들 때 `committee_name`을 `'법제사법위원회'`로 넣는다(`upsert_committee`를 거쳐 반환값을 쓴다).

### 관련위의 넷째 칸은 의견서제시일이다

`bills.py:62-63`의 주석은 이미 네 변형("처리일 · **의견서제시일** · 정부이송일 · 공포일자")을 알고 있는데 바로 아래 `STAGE_CELLS`에는 셋만 있다. **주석과 코드가 어긋난 채 4,241행이 NULL이었다.**

구현 세션은 관련위 표의 넷째 `<td>`의 실제 class를 확인해 `STAGE_CELLS`에 `date_processed`로 추가한다.

그리고 `result`는 **원천에 칸이 없으므로** NULL이 정상이다. 파싱 실패로 오해하지 않게 주석에 적는다.

### 공포정보는 법률마다 한 행이다

`2201193`(농어촌정비법 등 10개 법률):

```
2024-12-20 | 20581 | 농어촌정비법
2024-12-20 | 20581 | 도시농업의 육성 및 지원에 관한 법률
…
2024-12-20 | 20581 | 축산법
```

v1은 이 열 행으로 공포 **단계**를 열 개 만들고, `promulgated_law_name`에는 덮어쓰기로 마지막 하나(`축산법`)만 남겼다.

**고침**: 공포 단계는 `(공포일자, 공포번호)` 고유 조합당 한 행. 법률명은 `bill_promulgated_laws`에 `seq`를 붙여 전부 담는다.

## 원천 실측 — 의원 프로필 `/members/22nd/{slug}`

**`<dt>` 라벨 12개** (v1은 6개만 쓴다):

```
의원홈페이지 · 선거구 · 소속위원회 · 당선횟수 · 사무실 전화 · 사무실 호실
개별 홈페이지 · 이메일 · 보좌관 · 선임비서관 · 비서관 · 의원실 안내
```

- **성별 항목이 없다.** `members.sex`는 채울 길이 없다 → 삭제.
- **약력은 페이지에 있다.** 담지 않기로 했으므로 `profile_text` 삭제.
- 보좌진·의원실 안내는 담지 않는다.

### `term_count` — 한 글자 수정

당선횟수 `<dd>`의 원시 텍스트:

```
"\n\t\t\t\t\t\t\t\t\t\t\t\t\t\t\n\t\t\t\t\t\t\t\t\t\t\t\t\t\t\t재선(제19대, 제22대)"
```

`re.match`는 **문자열 맨 앞에서만** 매칭한다. 개행·탭으로 시작하므로 매번 실패하고 폴백 `value.split()[0]`이 괄호 안 공백에서 잘라 `재선(제19대,`를 만든다. `초선(제22대)`는 내부 공백이 없어 **우연히** 멀쩡했다.

```python
m = re.search(r"([가-힣0-9]+선\s*\([^)]*\))", value)   # match → search
```

`[가-힣]+선`도 `[가-힣0-9]+선`으로 넓힌다 — `3선`·`4선`은 ASCII 숫자로 시작해 원래 패턴이 아예 못 잡는다.

### `district` — 두 곳을 고친다

```python
text = tree.body.text(separator=" ")           # strip=True 가 없다
```

`meetings.py`의 같은 호출에는 `strip=True`가 있는데 여기만 빠져서, 조국 의원 행에 탭·개행이 대량 유입돼 **181자**가 됐다.

그리고 정규식이 잡은 토큰이 `'비례대표'`면 **`district`를 NULL로 둔다.** 스키마가 "비례대표는 NULL"이라 선언했는데 46건이 문자열 `'비례대표'`로 채워져 불변조건이 깨져 있었다.

## 최우선 — 발의자 14명 상한 조사

**구현 세션의 첫 작업이다.** 발의자 34,270명(13.7%)이 사라진 원인을 확정해야 다른 것을 고칠 의미가 있다.

### 확인된 것

```sql
SELECT n, COUNT(*) FROM (SELECT bill_no, COUNT(*) n FROM bill_proposers GROUP BY 1) GROUP BY 1 ORDER BY 1 DESC;
-- 최대가 14. 15 이상 0건. 제목이 말하는 최대는 191명.
```

`bills.py:446-449`의 `expected=len(proposers)`가 자기 자신을 검사해 **`replace_children`의 부분 실패 방어가 상시 무력화**돼 있다. 그래서 원천이 일부만 줘도 그대로 커밋되고 완결로 위장한다.

### 확인해야 할 것

`billProposer.do` 팝업을 **브라우저로 직접 열어** 다음을 본다.

1. 191명짜리 의안(제목에 `등 191인`)의 팝업이 실제로 몇 명을 보여주는가 — 화면에 전부 나오는데 우리가 14명만 파싱하는 것인가, 아니면 응답 자체가 14명인가.
2. 응답이 14명이면 **페이징 파라미터**가 있는가(`pageIndex`·`rowsPerPage` 등). 네트워크 탭에서 XHR을 본다.
3. 대표발의와 공동발의를 가르는 마크업이 무엇인가 — **공동대표발의 209건**(`최형두의원ㆍ박수현의원ㆍ이해민의원 등 33인`, 최대 3명)을 파서가 전부 잡는지 함께 확인한다.

> `claude-in-chrome`으로 확인한다. `read_network_requests`로 XHR 파라미터를 보는 것이 가장 빠르다.

### 고침 (원인과 무관하게 함께 한다)

```python
expected = parse_proposer_count(bill.title)   # '등 N인' → N, 패턴 없으면 1
dbm.replace_children(db, 'bill_proposers', 'bill_no', bill_no, rows, expected=expected)
```

불일치하면 `PartialListError`를 던져 `collect_failures(target_kind='bill_proposer')`에 남기고 **`detail_collected_at`을 쓰지 않는다.** 그래야 다음 실행이 다시 시도한다. `bills.py:108`의 목록 파서가 이미 같은 정규식을 갖고 있으니 재사용한다.

⚠️ `외 N인` 변종을 함께 처리한다 — `(김은혜의원 등 21인 외 1인)` 꼴이 44건이고, 이것 때문에 `proposer_kind='의원'`인 82건의 발의자 요약이 NULL이었다.

## `verify.py`에 추가할 것

`verify.py`는 "국회 사이트가 바뀌었나"를 DB 없이 본다. 이번에 드러난 함정들이 **원천 구조 변경에 취약한 지점**이므로 여기에 넣는다.

- 공포정보 표에 `공포법률` 칸이 있는가 (일괄개정 의안 하나로)
- 관련위 표의 넷째 칸이 여전히 `의견서제시일`인가
- 체계자구 표 캡션이 여전히 `법사위 …`인가
- **발의자 팝업이 `등 N인`과 같은 수를 돌려주는가** ← 이번 사고의 재발 방지
- 의원 페이지 `<dt>`에 `당선횟수`가 있는가

`verify.py`가 통과해도 파서가 깨질 수 있는 틈은 남는다. 이건 원천 구조의 **모양**만 보고 **값의 완결성**은 안 보기 때문이다 — 값 쪽은 `audit.py`의 새 게이트가 맡는다([03번](03-갱신-설계.md)).
