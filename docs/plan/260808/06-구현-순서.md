# 구현 순서

각 단계는 **검증 기준을 만족해야 다음으로 넘어간다.** "대충 되는 것 같다"로 넘어가면 뒤에서 원인을 찾느라 몇 배를 쓴다.

- [ ] `.tmp/Naver-News/.claude/skills/News/SKILL.md` — 같은 사용자의 같은 모양 스킬. 문체와 판단의 본보기다
- [ ] `.tmp/Naver-News/.claude/skills/News/Scripts/newsdb.py` — 스키마 주석을 어떻게 쓰는지, 원장을 어떻게 다루는지
- [ ] `.tmp/Naver-News/.github/workflows/*.yml` — self-hosted 러너와 워치독의 근거
- [ ] 이 계획의 [02-데이터-원천.md](02-데이터-원천.md) 전체

**검증:** News의 `newsdb.py`가 왜 `articles`에 상태 컬럼을 두지 않았는지 한 문장으로 설명할 수 있다.

## 1단계 — 스키마

[03-스키마.md](03-스키마.md)의 DDL을 `db.py`에 옮기고 `selftest`를 만든다.

**검증:**
- `uv run db.py selftest --db /tmp/t.db` 전부 통과
- `sqlite3 /tmp/t.db .schema`를 읽고 **테이블 간 관계를 전부 말할 수 있다.** 못 하면 주석이 부족한 것이다
- `selftest`가 실제 `CONGRESS.db`를 지목하면 거부한다

## 2단계 — 의원 명부

가장 작고(299건) 가장 먼저 필요하다(다른 전부가 FK로 참조).

1. `findNaasThx01.json` 호출 → `members` 적재
2. 각 slug의 상세 페이지 → 프로필·위원회 보강
3. `member_committees` 적재

**검증:**
- `SELECT COUNT(*) FROM members WHERE is_incumbent=1` == 명부 `resultCnt` (실측 299)
- `open_na_id`가 전부 고유하고, `mona_cd`도 전부 고유하다
- 동명이인이 있다면 이름은 같고 slug는 다른 행으로 들어와 있다
- 위원회가 둘인 의원(예: 김현 — 과방위·예결위)이 `member_committees`에 2행이다
- `committees`에 위원회가 자동 등록됐고, 유사 중복(공백만 다른 두 행)이 없다

> `pageLink=doActionList.goPage`를 빼먹으면 **200 OK에 빈 본문**이 온다. JSON 파싱 에러로만 드러나므로 여기서 막히면 이 문단을 떠올려라.

## 3단계 — 의안 목록 (전체 의안)

`findSchPaging.do`를 `rows=1000`으로 21회 호출한다.

**폼 63개 필드를 전부 보내야 한다** — 빈 값을 생략하면 총건수만 오고 행이 안 온다.

**검증:**
- `SELECT COUNT(*) FROM bills` ≈ 20,600 (수집 시점에 따라 증가)
- 숫자 의안번호가 20,510건이고 `ZZ` 형식이 88건이다 (전수 실측값)
- `bill_id` 접두어가 `PRC_`와 `ARC_` 둘 다 들어와 있다 (약 20,128 / 470)
- **의안번호 구멍이 0이다** ([04번](04-수집-설계.md)의 질의)
- `bill_id`가 전부 고유하다
- `title`에 `계류의안`·`처리의안` 배지 텍스트가 섞이지 않았다
- `bill_kind` 분포를 눈으로 본다 — 법률안이 대부분이고 예산안·결의안 등이 섞여 있어야 정상

## 4단계 — 의안 상세 (법률안만)

여기서 [04번](04-수집-설계.md)의 **속도 실측**을 한다. 200건으로 2/4/6/8 rps를 재고 기본값을 정한 뒤 전체를 돌린다.

한 의안 = 한 트랜잭션: `bills`의 상세 컬럼 + `bill_stages` + `bill_proposers` + `bill_meetings` (+ 표결), 마지막에 `detail_collected_at`.

> ⚠️ **`billInfo.do`에 `billId`만 보내면 접수정보·정부이송·공포 테이블이 조용히 빠진다.** GET 응답의 숨은 input을 통째로 되돌려 보내야 7개가 다 온다. 에러가 안 나므로 이걸 모르면 "공포된 법률이 없다"고 오판하게 된다.

**먼저 소수로 검증한다.** [02번](02-데이터-원천.md)의 예제들로 파서를 맞춘 뒤 전체를 돌려라:

| 예제 | 확인할 것 |
|---|---|
| `PRC_W2E6F0D7E1C0A1B6J1J2H3I6H1H9G1` (접수 단계) | 단계가 접수뿐일 때 빈 테이블을 어떻게 다루나 |
| `PRC_K2L5T1R2S1Q6R0P9Q1Y7Y3X5V9V9U4` (대안반영폐기) | `selRefBillId`가 잡히나. `관련위 심사정보` 테이블을 처리하나 |
| `PRC_X2V5W0U7V2D9D1B1C3A4B0Z2H9I6G9` (수정가결) | 표결 XHR이 잡히나. 찬성 193·반대 1·기권 2가 정확히 들어오나 |
| `PRC_R2V4H1W1T2K5M1O6E4Q9T0V7Q9S0U0` (공포 완료, AI 기본법) | 테이블 7개가 다 오나. 공포일 2025-01-21·공포번호 20676·공포법률명이 잡히나 |
| `ARC_Z2Z6J0U7B1W5I1L0Z5S6A0G5H0Z1Q1` (정부제출) | `ARC_` 접두어를 처리하나. 대표발의 카드가 없는 것을 정상으로 다루나 |

**검증:**
- 법률안 중 `detail_collected_at`이 NULL인 행이 0 (실패 원장 제외)
- 표결이 있는 의안에서 `yes + no + abstain == present`
- `bill_votes` 행 수 == `yes + no + abstain`
- `bill_proposers`에서 `role='대표발의'`가 없는 의안이 0 (정부제출은 예외 — 확인 필요)
- `bills.alt_bill_id`가 가리키는 `bill_id`가 전부 `bills`에 있다 (백필 완료 후)
- 모든 `bill_votes.open_na_id`가 `members`에 있다

## 5단계 — 회의록 트리

`/mnts/async/…` 엔드포인트의 파라미터를 먼저 알아내야 한다 ([07번](07-미해결-확인사항.md) 1번). **막히면 우회로가 있다** — 4단계에서 `bill_meetings`에 이미 쌓인 `conference_id`로 시작하고, 트리는 나중에 보강한다.

`class_id_sch` 2·3·4·5·6을 각각 훑어 `meetings` 메타를 채운다.

**검증:**
- `committee_class` 다섯 종류가 전부 있다
- 소위원회 회의가 `is_subcommittee=1`로 들어와 있다
- `bill_meetings`의 `conference_id` 중 `meetings`에 없는 것이 (본회의를 빼면) 0 — 있으면 트리가 빠뜨린 것이다

## 6단계 — 회의록 본문

한 회의 = 한 트랜잭션: `meetings` + `meeting_speakers` + `meeting_utterances` + `meeting_agenda`.

먼저 회의록 56297로 파서를 맞춘다. 기대값은 실측돼 있다:

```
발언 블록 105개 · /members/ 링크 있음 61 · 없음 44
안건 122개
메타: 제22대국회 제432회 (임시회) 제3차 과학기술정보방송통신위원회(2026.02.25.)
```

**검증:**
- 위 숫자가 그대로 재현된다
- `meeting_speakers.open_na_id`가 NULL인 화자의 `position`이 `과학기술정보통신부제2차관` 같은 비의원 직위다
- `meeting_utterances`에 `bill_no` 컬럼이 **없다**
- 수집 범위 회의 중 발언이 없는 회의가 0 (실패 원장 제외)
- 발언 본문에 HTML 태그 잔재가 없다

## 7단계 — 불변조건과 감사

[04번](04-수집-설계.md)의 불변조건 여섯 개를 `collect.py`의 stdout JSON으로 낸다. `--audit-only`가 락 없이 같은 값을 낸다.

**검증:** 일부러 행을 지우고 해당 불변조건이 실제로 빨간불이 되는지 본다. **빨간불이 나오는 것을 본 적 없는 감사기는 감사기가 아니다.**

[05-스킬-구성.md](05-스킬-구성.md)대로 `SKILL.md`를 쓴다. 스키마가 이미 말하는 것을 반복하지 마라.

**검증:**
