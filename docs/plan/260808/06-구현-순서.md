## 2단계 — 의원

여기서 만드는 것은 **slug 하나로 `members` 행을 채우는 함수**다. 명부 API가 막혀 있어서([07번](07-미해결-확인사항.md)) 시작 시점에 받을 수 있는 의원 목록이 없고, 그래서 이 단계의 산출물은 "299명이 적재된 테이블"이 아니라 **다른 도메인이 slug를 만날 때마다 부르는 보강기**다.

1. `members_seed.json`이 있으면 읽어 `members` 적재 (`mona_cd` 포함). 없으면 건너뛴다 — **실패가 아니다**
2. `upsert_member(slug, 힌트)` — 없으면 스텁을 만들고, `/members/22nd/{slug}` 상세로 프로필·`is_incumbent`·위원회를 채운다
3. `member_committees` 적재

**검증:**
- 시드가 있으면 `SELECT COUNT(*) FROM members WHERE is_incumbent=1` == 시드 `resultCnt`. 없으면 이 항은 판정하지 않는다
- `open_na_id`가 전부 고유하다. `mona_cd`는 **NULL이 여럿이어도 정상**이고, NULL이 아닌 것끼리는 고유하다
- `is_incumbent` 판정이 맞다 — `KIMHyun`은 1, **`CHUNJAESOO`는 0**(`jeonzik_name` 클래스). 둘 다 상세 페이지가 200이다
- 전직 의원은 `member_committees`가 **비는 것이 정상**이다. 파싱 실패로 처리하면 안 된다
- 동명이인이 있다면 이름은 같고 slug는 다른 행으로 들어와 있다
- 위원회가 둘인 의원(예: 김현 — 과방위·예결위)이 `member_committees`에 2행이다
- `committees`에 위원회가 자동 등록됐고, 유사 중복(공백만 다른 두 행)이 없다
- **같은 slug로 두 번 불러도 행이 늘지 않고 이미 채운 값이 지워지지 않는다** — 이 함수는 뒤 단계에서 수만 번 불린다

## 3단계 — 의안 목록 (전체 의안)

`findSchPaging.do`를 `rows=1000`으로 21회 호출한다.

폼은 `/bill/bi/bill/sch/detailedSchPage.do`에 있고 필드가 63개다. **63개를 다 보내는 것만으로는 부족하다 — `reqPageId=billSrch`를 채워야 행이 온다.** 빈 문자열이면 200에 총건수(20,598)와 페이지네이터는 정확히 오는데 목록만 0행이라, 필터를 잘못 걸었다고 오판하기 쉽다. `_csrf`는 `form`이 아니라 `global-hidden-form`에 있다.

**검증:**
- `SELECT COUNT(*) FROM bills` ≈ 20,600 (수집 시점에 따라 증가)
- 숫자 의안번호가 20,510건이고 `ZZ` 형식이 88건이다 (전수 실측값)
- `bill_id` 접두어가 `PRC_`와 `ARC_` 둘 다 들어와 있다 (약 20,128 / 470)
- **의안번호 구멍이 0이다** ([04번](04-수집-설계.md)의 질의)
- `bill_id`가 전부 고유하다
- `title`에 `계류의안`·`처리의안` 배지 텍스트가 섞이지 않았다
- `bill_kind` 분포를 눈으로 본다 — 법률안이 대부분이고 예산안·결의안 등이 섞여 있어야 정상

## 4단계 — 회의록 트리

[02번](02-데이터-원천.md) 7절의 열거 프로토콜을 그대로 옮긴다. **끝까지 돌려 본 코드가 이미 있고 기준값도 실측돼 있다.**

```
class_id_sch ∈ {2,3,5,6}                      ← 위원회형
  → 트리 GET에서 a.tit.cmit[id^=cmit_]의 data-cmit 수집
    → cmit.do (cmit_cd_sch=코드, sess_sch 비움) → 그 위원회의 22대 전체 회의 id

class_id_sch = 4                              ← 예결위만 트리 최상위가 회기다
  → 트리 GET에서 data-sess 수집
    → cmit.do (sess_sch=회기, cmit_cd_sch 비움)
```

**`sessCmit.do`는 쓰지 않는다.** `sess_sch`를 비우면 그 위원회의 22대 전체가 한 번에 오므로 회기를 돌 이유가 없다 — 회기마다 돌면 요청이 14배가 된다(국회운영위 45건 대 4건).

> **id만 모으지 마라 — `class_id_sch`를 짝지어 보존한다.** `meetings.committee_class`는 `NOT NULL`인데 **본문 헤더 어디에도 그 값이 없다**(02번 8절 실측). 여기서 버리면 5단계 INSERT에서 채울 수 없어 트리를 다시 훑어야 한다. "목록은 id만 열거한다"는 원칙의 유일한 예외다.

**검증:** 실측 기준값이 그대로 나와야 한다.

| class | 종류 | 트리 노드 | 회의 id |
|---|---|---|---|
| 2 | 상임위 | 20 | 1,516 |
| 5 | 국정감사 | 18 | 317 |
| 3 | 특위 | 14 | 112 |
| 4 | 예결위 | **회기 8** | 67 |
| 6 | 국정조사 | 5 | 44 |
| | **합계** | 70요청·30초 | **2,056** |

- **예결위(class=4)가 67건 나왔다** — 트리에 위원회 노드가 0개라 표준 경로면 에러 없이 0회 돌고 끝난다. 0이면 별도 경로를 안 탄 것이다
- `cmit.do`를 `sess_sch` **비워서** 불렀다 — 채우면 그 회기만 온다
- `cmit_chk=all`이면 소위원회 회의가 상위 위원회 응답에 함께 온다. 소위를 따로 훑지 않는다
- 요청에 `X-Requested-With: XMLHttpRequest`가 있다 — 없으면 **200에 id 0개**가 온다

## 5단계 — 회의록 본문 (2,056건)

한 회의 = 한 트랜잭션: `meetings` + `meeting_speakers` + `meeting_utterances` + `meeting_agenda`.

먼저 56297로 파서를 맞춘다. 기대값은 실측돼 있다:

```
.man 블록 105개 · /members/ 링크 있음 61 · 없음 44
spk_sub 요소 347개          ← 문자열 raw count 694와 다르다. 요소 단위로 세라
안건 122개
```

> ⚠️ **한 회의록으로 파서를 맞추면 나머지 네 종류에서 깨진다.** 헤더 형식이 종류마다 다르다([02번](02-데이터-원천.md) 8절의 실측표). 아래 여섯 건으로 함께 맞춰라.

| id | 확인할 것 |
|---|---|
| `56297` (상임위) | 기준값 재현. `<p class="num">제3호</p>`에서 `sitting_no=3`을 뽑나 — **제목 줄엔 차수가 없다** |
| `57051` (상임위 소위) | `국회운영위원회회의록 (국회운영개선소위원회)` → `is_subcommittee=1`, `committee_name`=소위, `parent_committee`=국회운영위원회 |
| `54608` (예결위 소위) | 같은 규칙이 예결위에서도 도나 |
| **`52240` (특위)** | **`대법관(노경필·박영재·이숙연)임명동의에관한인사청문특별위원회회의록` — 괄호가 이름 안에 있다. `is_subcommittee=0`이어야 한다.** 1이 나오면 소위 규칙을 「회의록」 뒤로 앵커하지 않은 것이다 |
| **`51889` (국정감사)** | **`2024년도 국정감사 …위원회회의록` — 회기·차수가 없고 `<p class="num">`도 없다.** `session_no`·`sitting_no`가 NULL로 들어가야 하고, 파싱 실패로 처리하면 안 된다 |
| `55981` (국정조사) | 상임위와 같은 형식임을 확인 — 국정감사만 예외라는 것의 대조군 |

**검증:**
- 위 여섯 건이 전부 의도한 값으로 들어간다
- `meetings` 행 수 == 4단계가 열거한 id 수 (2,056)
- `committee_class` 분포가 4단계의 class별 건수와 일치한다
- **`session_no IS NULL`인 행이 정확히 국정감사 317건이다** — 다른 종류에 NULL이 있으면 헤더 파싱이 샌 것이다
- `meeting_speakers.open_na_id`가 NULL인 화자의 `position`이 `과학기술정보통신부제2차관` 같은 비의원 직위다
- `meeting_utterances`에 `bill_no` 컬럼이 **없다**
- 발언이 없는 회의가 0 (실패 원장 제외)
- 발언 본문에 HTML 태그 잔재가 없다
- `committees`에 소위원회가 등록되고 `parent_committee`가 채워졌다. **이름에 괄호가 든 위원회가 쪼개지지 않았다**

## 6단계 — 의안 상세 (법률안만)

여기서 [04번](04-수집-설계.md)의 **속도 실측**을 한다. 200건으로 2/4/6/8 rps를 재고 기본값을 정한 뒤 전체를 돌린다.

한 의안 = 한 트랜잭션: `bills`의 상세 컬럼 + `bill_stages` + `bill_proposers` + `bill_meetings` (+ 표결), 마지막에 `detail_collected_at`.

> ⚠️ **`billInfo.do`에 `billId`만 보내면 접수정보·정부이송·공포 테이블이 조용히 빠진다.** GET 응답의 숨은 input을 통째로 되돌려 보내야 7개가 다 온다. 에러가 안 나므로 이걸 모르면 "공포된 법률이 없다"고 오판하게 된다.

**먼저 소수로 검증한다.** [02번](02-데이터-원천.md)의 예제들로 파서를 맞춘 뒤 전체를 돌려라:

| 예제 | 확인할 것 |
|---|---|
| `PRC_W2E6F0D7E1C0A1B6J1J2H3I6H1H9G1` (접수 단계) | 단계가 접수뿐일 때 빈 테이블을 어떻게 다루나 |
| `PRC_K2L5T1R2S1Q6R0P9Q1Y7Y3X5V9V9U4` (대안반영폐기) | `selRefBillId`가 잡히나. `관련위 심사정보` 테이블을 처리하나 |
| `PRC_X2V5W0U7V2D9D1B1C3A4B0Z2H9I6G9` (수정가결) | 표결 XHR이 잡히나. 찬성 193·반대 1·기권 2가 정확히 들어오나 |
| `PRC_R2V4H1W1T2K5M1O6E4Q9T0V7Q9S0U0` (공포 완료, AI 기본법) | 테이블 7개가 다 오나. **공포번호 20676·공포법률명이 안 비나** — 비면 `billInfo.do`에 잘못된 form을 보낸 것이다 |
| `PRC_O2N5B0A2A2G5E1H4Z3B8V3K4T3R5P6` (재의 부결, 상법 2208496) | `<pre class="bill_memo">`를 잡고 `reconsideration_result='부결'`로 파싱하나. **목록 의결결과는 `원안가결`로 오는데 실제로는 부결이다** |
| `ARC_Z2Z6J0U7B1W5I1L0Z5S6A0G5H0Z1Q1` (정부제출) | `ARC_` 접두어를 처리하나. 대표발의 카드가 없는 것을 정상으로 다루나 |

**검증:**
- 법률안 중 `detail_collected_at`이 NULL인 행이 0 (실패 원장 제외)
- **`reexamYn='Y'`인 28건의 `reconsideration_result`를 전수로 눈으로 확인한다** — 파싱이 맞는지 볼 수 있는 마지막 지점이다
- 표결이 있는 의안에서 `yes + no + abstain == present`
- `bill_votes` 행 수 == `yes + no + abstain`
- `bill_proposers`에서 `role='대표발의'`가 없는 의안이 0 (정부제출은 예외 — 확인 필요)
- `bills.alt_bill_id`가 가리키는 `bill_id`가 전부 `bills`에 있다 (백필 완료 후)
- 모든 `bill_votes.open_na_id`가 `members`에 있다
- **`bill_meetings`의 `conference_id` 중 `meetings`에 없는 것이 본회의를 빼면 0** — 있으면 4단계 트리가 빠뜨린 회의다. 두 경로(트리 · 의안 상세 링크)를 교차검증하는 자리이고, 회의록을 먼저 받아 두었기 때문에 여기서 바로 판정된다

## 7단계 — 불변조건과 감사

[04번](04-수집-설계.md)의 세 묶음을 전부 `collect.py`의 stdout JSON으로 낸다 — **게이트 9 · 조건부 1 · 보고값 5.** 각 항목은 `pass`·`fail`·`skip` 중 하나이고, 게이트에 `fail`이 하나라도 있으면 실행이 실패다. `--audit-only`가 락 없이 같은 값을 낸다.

**검증: 일부러 망가뜨려 빨간불을 본다.** 항목마다 한 번씩 한다 — **빨간불이 나오는 것을 본 적 없는 감사기는 감사기가 아니다.**

- 의안 한 행을 지운다 → `bill_no_gaps`가 1이 된다
- 가장 작은 의안번호 행을 지운다 → **`bill_no_gaps`는 여전히 0인데 `bill_no_min`이 튄다.** 이 둘을 따로 둔 이유가 여기서 보인다
- `meeting_utterances`를 한 회의만 지운다 → `meeting_bodies_missing`이 1
- 어떤 (위원회, 회기)의 제2호 회의를 지운다 → `sitting_gaps`가 1
- **국정감사 회의를 지워 본다 → `sitting_gaps`가 여전히 0이다.** 이건 버그가 아니라 [04번](04-수집-설계.md)에 적힌 알려진 사각지대이고, **직접 확인해 두어야 나중에 그 0을 믿지 않는다**
- `members_seed.json`을 치운다 → `incumbent_count`가 `fail`이 아니라 **`skip`**이다
