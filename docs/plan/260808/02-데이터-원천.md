# 데이터 원천 — 실측 정찰 결과

이 문서의 내용은 **2026-08-08에 `claude-in-chrome`으로 실제 호출해 확인한 것**이다. "아마 이럴 것"은 적지 않았고, 확인하지 못한 것은 [07-미해결-확인사항.md](07-미해결-확인사항.md)로 뺐다.

전부 평범한 HTTP POST/GET이다. **수집은 Python `httpx`로 직접 친다** — 브라우저 자동화는 정찰용이었고, 의안 2만 건 규모에서는 며칠이 걸리고 탭 하나가 죽으면 무너진다.

## 세 개의 호스트

| 호스트 | 담당 | 비고 |
|---|---|---|
| `likms.assembly.go.kr` | 의안(법률안) 목록·상세·표결·발의자 | 의안정보시스템 |
| `record.assembly.go.kr` | 회의록 트리·본문 | 국회회의록 |
| `www.assembly.go.kr` | 의원 명부(JSON)·의원 상세 | 국회 홈페이지 |

`open.assembly.go.kr`(열린국회정보)는 **쓰지 않는다.** 의원 검색 페이지가 있지만 목록이 JS로 주입되고, 같은 데이터를 `www.assembly.go.kr`가 깨끗한 JSON으로 준다.

## 1. 의안 목록

```
POST https://likms.assembly.go.kr/bill/bi/bill/sch/findSchPaging.do
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
X-Requested-With: XMLHttpRequest
```

**응답은 JSON이 아니라 HTML 조각**이다. `<tr>` 행 목록 + 페이지네이터 + 인라인 `<script>`가 함께 온다.

### 파라미터

폼(`document.forms['form']`)에 필드가 **63개** 있고, 그중 일부만 채워도 나머지는 빈 문자열로 보내야 한다. **빈 값을 생략하면 목록 행이 안 오고 페이지네이터만 온다** — 정찰 중 실제로 겪은 함정이다. 총건수는 정상적으로 오기 때문에 "필터는 먹었는데 행이 없다"로 보여 원인을 찾기 어렵다.

의미 있는 것만:

| 파라미터 | 값 | 뜻 |
|---|---|---|
| `ageFrom` / `ageTo` | `22` / `22` | 제안 대수 범위 |
| `fromPropDt` / `toPropDt` | `2026-08-06` | 제안일자 범위 (`YYYY-MM-DD`) |
| `page` | `1` | 1부터 |
| `rows` | `1000` | **1000 확인됨** |
| `billKind` | (비움) | 의안종류. **비워 둔다 — 전체 의안을 받아야 한다** |
| `_csrf` | 페이지의 `input[name=_csrf]` | |

그 밖에 `fromSubmitDt`/`toSubmitDt`(접수일), `fromGovTransDt`/`toGovTransDt`(정부이송일), `procGbnCd`(처리구분), `cmtResultCd`(위원회 처리결과), `srchCmtId`(소관위) 등의 범위·필터가 있다. 갱신 전략에서 쓸 수 있다.

### 응답에서 뽑는 것

행마다 `data-` 속성으로 키가 직접 박혀 있다. 텍스트 파싱이 필요 없다.

```html
<tr>
  <td>2220510</td>
  <td><a data-bill_no="2220510"
         data-bill-id="PRC_A2I6J0H8H0F7E1F4M1N1M2M5K4J5K6"
         onclick="goDetailPage(this);">…</a></td>
  …
</tr>
```

컬럼 순서: `의안번호 · 의안명 · 제안자구분 · 제안일자 · 의결일자 · 의결결과 · 제안이유(아이콘) · 심사진행상태`

의안명 셀에는 `계류의안` / `처리의안` 같은 상태 배지 텍스트가 앞에 붙는다. **의안명만 떼어낼 때 이걸 같이 가져오지 않도록 주의하라** — 배지는 별도 자식 요소다.

### 실측 수치

- 22대 전체 의안: **20,598건** (2026-08-08 기준)
- `rows=1000` 요청 1회: 응답 **1.6MB**, **1.9초**
- `rows=100`은 1.27초 — 요청당 고정비가 크므로 **1000을 쓰는 게 압도적으로 유리하다**
- 22대 전체를 훑는 데 **21회 요청**이면 된다

### 의안번호는 빈틈없이 연속이다 (가장 중요한 발견)

`rows=1000` 한 페이지를 검사한 결과:

```
행 1000개 → 의안번호 1000개 전부 고유, PRC_ 코드 1000개 전부 고유
범위 2219511 ~ 2220510  (= 정확히 연속된 정수 1000개, 구멍 0)
```

의안번호는 `22` + 5자리 일련번호다. **그래서 완결성을 산술로 증명할 수 있다** — "최소 의안번호부터 최대까지 전부 있는가"를 SQL 한 줄로 묻는다. News 스킬의 셀 원장보다 강한 보증이다.

이 성질은 **목록을 전체 의안으로 받을 때만 성립한다.** 법률안만 받으면 예산안·결의안 자리에 구멍이 생기고, 그 구멍이 비법률안인지 수집 실패인지 구분할 수 없게 된다. `billKind`를 채우고 싶어지면 이 문단을 다시 읽어라.

## 2. 의안 상세

```
GET https://likms.assembly.go.kr/bill/bi/billDetailPage.do?billId={PRC_…}
```

**완전한 서버 렌더링이다.** 페이지 로드 중 XHR이 하나도 없다(표결 탭 제외 — 아래 3번). 한 번의 GET으로 심사 정보 전체가 온다.

### 숨은 input에 구조화 메타데이터가 있다

텍스트를 파싱하기 전에 `input[type=hidden]`을 먼저 봐라. 훨씬 안정적이다.

| 필드 | 예시 | 뜻 |
|---|---|---|
| `billNo` | `2215928` | 의안번호 |
| `billId` | `PRC_K2L5…` | 의안 ID |
| `billKindCd` | `법률안` | **의안종류. 이름에서 추정할 필요가 없다** |
| `selRefBillId` | `PRC_Z2Z6…` | **대안반영폐기 시 흡수한 대안 법률안** |
| `reexamYn` | `N` | **재의(대통령 거부권 후 재의결) 여부** |
| `currCmtName` | `위원회 심사` | 현재 심사 단계 |
| `withdrawCnt` | `0` | 철회 건수 |
| `tmprAnYn` | `N` | (미확인 — 임시안 추정) |
| `headMemoInfo` | `비용추계요구서 제출됨.` | 상단 메모 |

`selRefBillId`가 특히 중요하다. 이전 프로젝트는 OpenAPI에 대안 관계 필드가 없어 이 값을 따로 스크래핑해야 했다(22대 대안반영폐기 3,676건 + 수정안반영폐기 39건). 우리는 처음부터 이 페이지를 긁으므로 공짜로 따라온다.

### 심사 단계 테이블

`<table>`에 `<caption>`이 붙어 있어 **caption 텍스트로 어느 테이블인지 판별한다.** 클래스나 순서에 의존하지 마라 — 의안마다 존재하는 테이블이 다르다.

| caption 시작 | 컬럼 |
|---|---|
| `의안접수정보` | 의안번호 · 제안일자 · 제안자 · 제안회기 · 문서 |
| `소관위 심사정보` | 소관위원회 · 회부일 · 상정일 · 처리일 · 처리결과 · 문서 |
| `소관위 회의정보` | 회의명 · 회의일 · 회의결과 · **회의록** |
| `소위 심사정보` | 소위원회 · 회부일 · 상정일 · 처리일 · 처리결과 |
| `관련위 심사정보` | 관련위원회 · 회부일 · 상정일 · 의견서제시일 · 문서 |
| `법사위 체계자구 심사정보` | 회부일 · 상정일 · 처리일 · 처리결과 · 체계자구검토보고서 |
| `법사위 회의정보` | 회의명 · 회의일 · 회의결과 · 회의록 |
| `본회의 심의정보` | 상정일 · 의결일 · 회의명 · 회의결과 · 회의록 |
| `정보이송정보` | 정부이송일 · 문서 |

> `정보이송정보`는 오타가 아니다 — 국회 쪽 caption이 실제로 그렇게 적혀 있다(화면 제목은 "정부이송정보"). **caption으로 매칭한다면 이 오타를 그대로 써야 한다.**

`관련위 심사정보`는 예제 하나에만 있었다. 테이블 목록을 고정으로 가정하지 말고 **caption을 보고 있는 것만 처리하라.**

### 회의록으로 이어지는 링크 (중요)

`소관위 회의정보` · `법사위 회의정보` · `본회의 심의정보`의 회의록 칸에 이런 링크가 있다:

```
https://record.assembly.go.kr/assembly/viewer/minutes/download/pdf.do?id=56297
```

**이 `id=56297`이 회의록 본문 URL(`xml.do?id=`)의 그 id와 같은 값이다.** 즉 의안 ↔ 회의록 조인이 의안 쪽에서 직접 나온다. 회의록 트리를 훑지 않고도 "이 법안이 논의된 회의"를 알 수 있다.

### 페이지 제목에서

`<title>`이 `[2214631] 소프트웨어 진흥법 일부개정법률안(이해민의원 등 13인) | 심사정보` 형식이라 의안번호·의안명·제안자 요약을 한 번에 얻을 수 있다.

## 3. 표결 정보

```
POST https://likms.assembly.go.kr/bill/bi/bill/detail/voteInfo.do
body: billId={PRC_…}&_csrf=…
```

**상세 페이지의 HTML에는 표결 정보가 없다.** 탭을 눌러야 이 XHR이 나간다 — 원문 HTML에 `재석`·`찬성`이 문자열로 존재하지 않는 것을 확인했다. 상세만 받고 표결이 없다고 판단하면 안 된다.

응답은 HTML. 뽑을 것:

- **요약**: 제안/표결일자, 발의자/제안자, `재석 196인 / 재적 299인`, `수정가결 196인 (찬성 193인, 반대 1인, 기권 2인)`
- **명단**: 찬성/반대/기권 각 탭에 `<ul><li>` 목록. 각 `<li>`가 의원 상세 링크를 갖는다:

```html
<li class="visible">
  <a href="https://www.assembly.go.kr/members/22nd/KANGKYUNGSOOK">
    <span class="pic"><img …></span>
    <span class="txt">…</span>
  </a>
</li>
```

**의원 코드(`monaCd`)는 없고 slug(`openNaId`)만 있다.** 그래서 `members`의 PK를 slug로 잡았다. 이름 문자열로 조인하면 동명이인에서 조용히 틀린다.

### 표결에 관한 함정

**불참은 기록되지 않는다.** 재적 299 / 재석 196이면 103명이 불참인데, 명단 탭은 찬성·반대·기권 셋뿐이다. `bill_votes`에 행이 없는 것은 "불참"이 아니라 **"이 표결에서 그 의원의 표를 우리가 모른다"**이다. 불참자를 세고 싶으면 재적·재석 숫자로 계산하고, 명단으로 유도하지 마라.

**대통령 거부권 후 재의결은 표결이 두 번이다.** 이전 프로젝트는 원표결만 얻었다. 우리 원천에서 두 번이 다 오는지는 미확인 — [07번](07-미해결-확인사항.md) 참조. `reexamYn` 필드가 단서다.

## 4. 발의자 명단

```
POST https://likms.assembly.go.kr/bill/bi/popup/billProposer.do
body: billId={PRC_…}&billNo={의안번호}&_csrf=…
```

응답 HTML에 의원마다 이렇게 온다:

```html
<a href="https://www.assembly.go.kr/members/22nd/LEEHAIMIN">이해민 李海珉 조국혁신당</a>
```

**한글명 · 한자명 · 정당 · slug를 한 번에 준다.** 탭이 `전체` / `발의의원 명단`으로 나뉘어 있어 대표발의와 공동발의를 가를 수 있다 — 정확한 가르는 법은 [07번](07-미해결-확인사항.md) 확인 항목이다.

실측: 의안 2215928(이해민의원 등 13인) → 의원 링크 13개.

### 같이 발견한 관련 엔드포인트

`/bill/bi/popup/assmMemb.do`, `/bill/bi/popup/assmMembSameName.do`, `/bill/bi/popup/selSameNmMemb.do`

**동명이인 전용 팝업이 따로 있다는 것은 이 데이터셋에 동명이인이 실재한다는 뜻이다.** slug를 키로 쓰는 판단의 근거이자, 이름 기반 조인을 절대 하지 말아야 할 이유다.

## 5. 의원 명부 — 유일한 진짜 JSON API

```
POST https://www.assembly.go.kr/portal/cnts/cntsNaas/findNaasThx01.json
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
X-Requested-With: XMLHttpRequest
```

### 파라미터 (전부 보내야 한다)

```
menuNo=600137  cntsDivCd=NAAS  unitCd=100022  pageIndex=1
pageLink=doActionList.goPage
hgNm=  polyCd=  cmitCd=  upOrigCd=  origCd=  sexGbn=  ageGbn=
reeleGbnCd=  electGbnCd=  hgNmMb=  ageCdMb=100022  polyCdMb=
cmitCdMb=  upOrigCdMb=  origCdMb=  sexGbnMb=  ageGbnMb=
reeleGbnCdMb=  electGbnCdMb=
```

**`pageLink=doActionList.goPage`가 없으면 빈 응답이 온다.** 200 OK에 본문 길이 0이라 JSON 파싱 에러로만 드러나고 원인 표시가 없다. 정찰 중 여기서 두 번 막혔다.

`unitCd=100022`가 제22대다. 대수를 넓힐 때 이 값을 바꾼다.

### 응답

```json
{
  "resultCnt": 299,
  "resultList": [{
    "rnum": "31",
    "monaCd": "86R9476S",
    "openNaId": "KIMMOONSOO",
    "hgNm": "김문수",
    "polyNm": "더불어민주당",
    "origNm": "전남광주통합특별시 순천시광양시곡성군구례군갑",
    "cmitNm": "교육위원회",
    "electGbnNm": "지역구",
    "reeleGbnNm": "초선",
    "sexGbnNm": "남",
    "unitNm": "제22대",
    "st": "22",
    "mImgUrl": "…", "mThumbImgUrl": "…", "mLinkUrl": "…"
  }],
  "paginationInfo": {…}, "pageNav": "…(HTML)…"
}
```

**`monaCd`가 국회 공식 의원 코드이고 `openNaId`가 우리가 다른 데서 만나는 그 slug다.** 둘을 잇는 유일한 지점이 이 엔드포인트다 — 표결·발언·발의자 어디에도 `monaCd`가 없기 때문이다.

실측 `resultCnt`: **299** (정원 300 중 1석 공석). 이 숫자가 완결성 대조 기준이 된다.

`origNm`이 `전남광주통합특별시 …`처럼 나오는 것은 오류가 아니라 행정구역 통합의 반영이다. 선거구명을 정규화하려 들지 마라.

한 페이지에 10건씩 온다. `pageIndex`를 올려 30페이지를 받거나, 페이지 크기 파라미터를 찾아본다([07번](07-미해결-확인사항.md)).

## 6. 의원 상세

```
GET https://www.assembly.go.kr/members/{대수}/{slug}
예: https://www.assembly.go.kr/members/22nd/KIMHyun
```

대수는 `22nd`처럼 **영문 서수**이고 이름 자리는 **한글이 아니라 slug**다.

**slug의 대소문자는 규칙이 없다** — `KIMHyun` · `CHOIMinhee` · `KANGKYUNGSOOK` · `LEEHAIMIN`이 전부 다른 패턴이다. 이름에서 slug를 만들어낼 수 없다. **반드시 명부 API의 `openNaId`나 링크의 href에서 가져와라.**

서버 렌더링이고 `<dl><dt>/<dd>`로 항목이 온다:

| 항목 | 예시 |
|---|---|
| 선거구 | `경기 안산시을` |
| 소속위원회 | `과학기술정보방송통신위원회, 예산결산특별위원회` (쉼표 구분) |
| 당선횟수 | `재선(제19대, 제22대)` + 각 대수 임기 |
| 사무실 전화 / 호실 | `02-784-8780` / `의원회관 313호` |
| 개별 홈페이지 / 이메일 | |

## 7. 회의록 트리

`record.assembly.go.kr`의 전체회의록 페이지는 **위원회 → 회기 → 차수** 3단 fold다. fold를 펼치는 비동기 엔드포인트가 따로 있다(`static/js/…/list.js`에서 확인):

```
/mnts/async/sess.do        회기 목록
/mnts/async/cmit.do        위원회 목록
/mnts/async/sessCmit.do    회기×위원회
/mnts/async/sessCmit2.do
/mnts/async/ord.do         차수(개별 회의) 목록  ← conference id가 여기서 나온다
/mnts/async/ApdxList.do    부록
/mnts/async/ZapdxList.do
```

진입 URL의 `class_id_sch`가 회의 종류를 가른다:

| 값 | 종류 |
|---|---|
| 2 | 상임위원회 |
| 3 | 특별위원회 |
| 4 | 예산결산특별위원회 |
| 5 | 국정감사 |
| 6 | 국정조사 |

```
https://record.assembly.go.kr/assembly/mnts/total/22.do?class_id_sch=2&cmit_chk=all
```

경로의 `22`가 대수다.

**각 async 엔드포인트의 정확한 파라미터는 확인하지 못했다** — [07번](07-미해결-확인사항.md)의 첫 번째 확인 항목이다. 트리를 훑는 대신 의안 상세에서 얻은 회의록 id를 쓰는 우회로가 있으니(2번 참조), 트리 파싱이 막히면 그쪽을 먼저 시도하라.

## 8. 회의록 본문 — 가장 깨끗한 원천

```
GET https://record.assembly.go.kr/assembly/viewer/minutes/xml.do?id={회의록id}&type=view
```

이름이 `xml.do`지만 **응답은 HTML**이다. 그리고 시맨틱 클래스가 붙어 있어 파싱이 안정적이다.

### PDF가 아니라 이 HTML을 쓰는 이유

PDF에서는 화자와 발언을 레이아웃 휴리스틱으로 추측해야 하지만, 여기서는 **필드가 이미 나뉘어 있다.**

```html
<div class="in_chk">…</div>
<div class="man">
  <a href="https://www.assembly.go.kr/members/22nd/KIMHyun">
    <span class="pic"><img …></span>
    <span class="txt">
      <span class="position">소위원장</span>
      <strong class="name">김현</strong>
      <span class="area">(경기 안산시을)</span>
    </span>
  </a>
</div>
<div class="talk">
  <div class="txt">
    <span class="spk_sub">정보통신방송법안심사소위원회 김현 위원장입니다.</span><br>
    <span class="spk_sub">우리 소위원회는 2월 24일 …</span><br>
    …
  </div>
</div>
```

- `.speaker` — 발언 블록
- `.man` — 화자 (`.position` 직위, `.name` 이름, `.area` 선거구)
- `.man a[href*="/members/"]` — **있으면 국회의원, 없으면 비의원**
- `.talk .spk_sub` — 발언 문단. 여러 개가 `<br>`로 이어진다

### 질의자/답변자 판별은 실측으로 확인됐다

회의록 56297(제22대 제432회 제3차 과학기술정보방송통신위원회, 2026-02-25):

```
발언 블록 105개
  ├ /members/ 링크 있음  61개  → 국회의원
  └ 링크 없음            44개  → 비의원
```

링크 없는 쪽의 `.position` 실제 값: `과학기술정보통신부제2차관` · `방송미디어통신위원장` · `과학기술정보통신부제1차관` · `우주항공청장` · `수석전문위원` · `전문위원`

링크 있는 쪽: `위원장` · `소위원장` · `소위원장대리` · `위원`

**직위 문자열로 분류하려 들지 마라.** 링크의 유무가 판별자다 — 직위는 종류가 열려 있고 회의마다 새로 생긴다.

### 화자는 발언보다 훨씬 적다

발언 블록 105개에 **고유 화자는 20명 안팎**이다. 그래서 `meeting_speakers`를 따로 두고 발언이 그것을 참조한다. 발언마다 직위·선거구를 반복하면 같은 사실이 수백 번 중복된다.

### 회의 메타데이터

본문 첫머리에 한 줄로 온다:

```
제22대국회 제432회 (임시회) 제3차 과학기술정보방송통신위원회(2026.02.25.)
```

대수 · 회기 · 회기종류 · 차수 · 위원회 · 일자가 전부 여기서 나온다.

페이지의 다른 섹션: `상정된 안건` · `안건정보` · `부록` · `영상회의록` · `발언자` · `회의정보`

### 상정 안건은 의안과 직접 연결된다

```html
<p class="tit_sm angun pl10">
  <a href="https://likms.assembly.go.kr/bill/billDetail.do?billId=PRC_O2M5V0V1T0U9S1T8R0S2Z3Y5Z1X3X8">
    100. 방송법 일부개정법률안(김현 의원 대표발의)(의안번호 2207480)
  </a>
</p>
```

`.angun` 요소가 **billId와 의안번호를 둘 다** 준다. 이 회의는 안건이 122개였다.

> ⚠️ **안건은 회의 단위이지 발언 단위가 아니다.** 회의가 어떤 안건을 상정했는지는 알 수 있지만, **개별 발언이 어느 안건에 대한 것인지는 알 수 없다.** 의원마다 질의에서 다루는 순서가 다르고, 안건을 하나씩 끝내고 넘어가는 방식이 아니기 때문이다. `meeting_utterances`에 `bill_no`를 두지 마라 — 그 컬럼은 채우는 순간 거짓이 된다.

여기의 의안 상세 URL이 `/bill/billDetail.do?billId=`로, 의안정보시스템의 `/bill/bi/billDetailPage.do?billId=`와 **경로가 다르다.** billId 값은 같다.
