# 미해결 확인사항

계획 세션이 **확인하지 못한 것**들이다. 각 항목에 "왜 못 했나"와 "어떻게 확인하나"를 적었다.

초안에는 13개가 있었지만 **대부분을 계획 세션에서 직접 확인해 해소했다.** 해소된 것은 아래 표로 옮겼고, 여기 남은 **둘**이 정말로 확인하지 못한 것이다. **둘 다 구현을 막지 않는다.**

**추정 위에 코드를 쌓지 마라.** 여기 있는 것을 확인 없이 가정하면, 틀렸을 때 증상이 엉뚱한 곳에서 나타나 원인을 찾는 데 몇 배가 든다.

---

## 1. 의원 명부를 브라우저 밖에서 받을 수 있는가 — 우선순위 높음

**명부 JSON API가 `curl`에서 403이다.** User-Agent · 세션 쿠키 · Referer · Origin · Accept를 다 갖춰도 본문 0바이트로 막힌다. 브라우저에서는 정상이다. 봇 차단으로 보이고, **우회는 시도하지 않았다.**

나머지(likms 의안, record 회의록, 의원 상세 페이지)는 전부 curl로 확인됐다.

**다만 위험이 크게 줄었다.** 떠난 의원까지 포함해 **모든 의원의 상세 페이지가 slug만 있으면 열린다**는 것이 확인됐고, 현직 여부도 그 페이지가 `jeonzik_name` 클래스로 알려 준다. 즉 명부 API 없이도 프로필과 `is_incumbent`를 다 채울 수 있다. **잃는 것은 `mona_cd`와 "현직 299명"이라는 권위 있는 총원 하나뿐이다.**

**시도 순서:**

1. **`httpx`로 그냥 해 본다.** curl과 TLS 스택이 달라 통과할 수 있다. 5분이면 판명된다
2. **의원 상세 페이지로 대체한다.** `/members/22nd/{slug}`는 curl로 잘 되므로, slug만 표결·발의자·발언에서 모으면 프로필 전체를 받을 수 있다
3. **명부만 브라우저로 받는다.** 299명이고 한 달에 한 번이면 충분하다. 수집 전체를 `httpx`로 두고 이 한 조각만 예외로 두는 편이 합리적이다

**스키마에 영향이 있다.** `mona_cd`는 이 JSON API에만 나오므로, 2·3번으로 가면 채우지 못할 수 있다. 그때는 `members.mona_cd`의 `NOT NULL UNIQUE`를 재판단해야 한다 — PK는 `open_na_id`라 조인은 멀쩡하다.

**페이지 크기 상한**(한 페이지 10건, `pageIndex` 30회)은 부수적인 미확인 사항이다. 어차피 299건이라 구현에 지장이 없다.

## 2. `tmprAnYn` 필드의 의미

의안 상세의 숨은 input에 있고 관측한 모든 의안에서 `N`이었다. 임시안 여부로 추정하지만 확인하지 못했다.

**모르면 저장하지 마라.** 의미를 모르는 컬럼은 나중에 누군가 잘못 해석한다.

## 계획 세션에서 해소한 것들 — 다시 재지 마라

근거 수치는 [02-데이터-원천.md](02-데이터-원천.md)에 있다.

| 초안의 질문 | 확인 결과 |
|---|---|
| 표결에 '불참' 명단 탭이 있는가 | **없다.** 찬성/반대/기권 셋뿐이고 응답에 '불참' 문자열이 아예 없다. 스키마의 `CHECK`와 "행 없음 ≠ 불참"이 맞다 |
| 재의결 법안의 표결이 두 번 오는가 | **한 번만 온다.** 상법 2208496(재의 대상)에 `재석`이 1회뿐. `bill_vote_summary` PK를 바꿀 필요가 없다 |
| 대표발의와 공동발의를 어떻게 가르나 | 상세 페이지 상단 **대표발의의원 카드**의 `/members/` 링크. 팝업은 대표발의를 전혀 표시하지 않는다 |
| 위원장·정부 제출의 발의자 | 대표발의 카드가 없고 `/members/` 링크도 없다. `proposer_kind`로 가른다 |
| 22대 최초 의안번호 | **2200001** |
| 의안번호가 정말 연속인가 | **전수 확인.** 20,510건이 2200001~2220510에 구멍 0·중복 0 |
| `PRC_` 코드의 문자 집합 | 속성에서 뽑으면 정확하다. 그리고 **정부제출은 `ARC_`다** |
| 법률명약칭 사전 | 1,034건 존재하나 커버리지가 낮고 언론 통칭이 없어 **사용 보류**로 결정 |
| 공포 단계 테이블의 모양 | **확인.** `공포정보 : 공포일자 · 공포번호 · 공포법률`. AI 기본법(2206772)에서 2025-01-21 / 20676 / '인공지능 발전과 신뢰 기반 조성 등에 관한 기본법' |
| 회의록 트리를 꼭 알아야 하나 | **아니다.** 회의 메타는 본문 첫머리에 다 있고, 목록은 id 열거만 하면 된다 |
| 떠난 의원의 상세 페이지가 살아 있는가 | **살아 있다.** 전재수 의원(`CHUNJAESOO`, 22대 중 사직) → HTTP 200 · 74KB · 정당·선거구 그대로. 게다가 `jeonzik_name` 클래스로 전직임을 스스로 표시한다 |
| 브라우저 밖(curl)에서도 되는가 | **대체로 된다.** likms·record·의원 상세는 200. 단 POST는 세션 쿠키가 필요하고, **명부 JSON API만 403**이다 |
| 회의록 id를 어떻게 빠짐없이 얻나 | **확인. 브라우저 없이 끝까지 돌렸다.** `sessCmit.do`(회기 목록) → `cmit.do`(회의 id). 국회운영위 제437회에서 4건을 얻어 화면의 트리와 일치 확인 |

## 계획 세션이 새로 발견한 함정 — 초안에 없던 것

| 발견 | 영향 |
|---|---|
| **의안 상세는 서버렌더링이 아니다** — 심사 단계는 `billInfo.do` XHR로 온다 | 의안 1건에 요청 2회가 최소. 초안의 "XHR 없음" 서술이 틀렸다 |
| **정부제출 의안의 billId는 `ARC_`** (실측 470건) | `PRC_`만 가정하면 조용히 누락 |
| **`ZZ22124` 형식 의안번호 88건** | `bill_no`를 INTEGER로 두면 깨진다. TEXT로 바꿨다 |
| **`billGbnCd=대안`** 숨은 필드 | 대안 여부를 이름에서 추정할 필요가 없다 |
| 위원장 934건 · 정부 601건 · 재의 28건 | 규모 감각. `proposerKind`·`reexamYn`이 검색 필터로 있다 |
| 소관위 처리결과에 `대안가결`이라는 값이 있다 | 처리결과 값 집합이 본회의와 위원회에서 다르다 |
| **`billInfo.do`에 `billId`만 보내면 테이블이 일부만 온다** | 접수정보·정부이송·공포가 조용히 빠진다. GET의 숨은 input을 되돌려 보내야 한다 |
| 공포일·정부이송일이 GET의 숨은 input에 있다 | `announceDt` · `govTransDt` |
| **공포법률명이 의안명과 다르다** | `…기본법안(대안)` → `…기본법`. 바깥 자료와 맞출 때 쓰는 이름 |
| 회의록검색 폼이 코드 사전이다 | 위원회 `22-2-AF-B`, 회기 `417`~`781`, **제22대 = `24`** |
