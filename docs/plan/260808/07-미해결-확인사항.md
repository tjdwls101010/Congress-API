# 미해결 확인사항

계획 세션이 **확인하지 못한 것**들이다. 각 항목에 "왜 못 했나"와 "어떻게 확인하나"를 적었다.

초안에는 13개가 있었지만 **대부분을 계획 세션에서 직접 확인해 해소했다.** 해소된 것은 아래 표로 옮겼고, 여기 남은 다섯이 정말로 확인하지 못한 것이다.

**추정 위에 코드를 쌓지 마라.** 여기 있는 것을 확인 없이 가정하면, 틀렸을 때 증상이 엉뚱한 곳에서 나타나 원인을 찾는 데 몇 배가 든다.

---

## 1. 회의록 트리 async 파라미터의 **값** — 우선순위 높음

엔드포인트와 파라미터 **이름**은 확보했다([02번](02-데이터-원천.md) 7절). 확보하지 못한 것은 **값**이다 — `sess_sch`(회기 코드) · `council_cd_sch`(위원회 코드) · `mnts_id_sch`가 각각 어떤 형식인지 모른다.

이름만으로 호출해 봤더니 200에 본문 16~47바이트(빈 응답)가 왔다. 즉 **값이 맞아야 내용이 온다.**

**확인 방법:** 트리 페이지에서 fold를 실제로 눌러 XHR 페이로드를 가로챈다. 의원 명부 API를 찾았던 것과 같은 방법이다 — 페이지 소스만 봐서는 안 보이고 **눌러야 드러난다.** 계획 세션에서 세 번 시도했으나 fold 요소를 정확히 집지 못했다(상단 내비 링크를 눌러 새 탭이 열렸다). 브라우저 개발자도구 Network 탭을 직접 보는 편이 빠를 수 있다.

**막히면 우회로가 있다:** 4단계에서 `bill_meetings`에 `conference_id`가 쌓인다. 그걸로 회의록 본문 수집을 시작하고 트리는 나중에 보강해도 된다. 다만 그러면 **의안과 무관한 회의(국정감사 등)를 놓치므로** 트리는 결국 뚫어야 한다.

## 2. 공포 단계 테이블의 실제 모양

정찰에 쓴 예제 중 **공포까지 간 법률을 끝내 찾지 못했다.** 재의 대상인 상법 2208496(원안가결)조차 `billInfo.do` 응답에 정부이송·공포 테이블이 없었다 — `소관위 심사정보` · `소관위 회의정보` · `본회의 심의정보` 셋뿐이었다.

그래서 `bill_stages`의 `'공포'` 단계와 `ref_no`(공포번호) 컬럼은 **여전히 추정이다.**

**확인 방법:** 목록에서 `procGbnCd=P`(처리의안)이고 제안일이 오래된 법률안을 골라 `billInfo.do`를 호출하고 caption 목록을 본다. 공포된 법률이 22대에 수백 건 있으므로 몇 건만 뒤지면 나온다.

**주의:** `lawStatus` 파라미터는 공포 여부가 아니라 **제정/전부개정/일부개정/헌법개정/폐지**를 가르는 필터다(실측). 공포로 거르는 필터는 못 찾았다.

## 3. 의원 명부 API의 페이지 크기 상한

한 페이지 10건이 기본이다. `pageIndex`를 30번 돌면 299명이 다 나오므로 **구현에 지장은 없다.** 한 번에 받을 수 있는지만 확인하지 못했다.

**확인 방법:** 요청 바디에 `recordCountPerPage` · `pageUnit` · `rows` 같은 흔한 이름을 넣어 본다. 안 되면 그냥 30번 돈다.

## 4. 전직(사퇴) 의원을 어떻게 받는가

현직 299명은 `unitCd=100022`로 받는다. **22대 중 사퇴·상실로 떠난 의원을 어떻게 조회하는지는 확인하지 못했다.** 그 사람들의 과거 표결·발의가 DB에 남아 있어야 조인이 안 끊긴다.

**확인 방법 두 가지. 2번부터 확인하라 — 되면 별도 명부 소스가 필요 없다.**

1. `open.assembly.go.kr/portal/assm/search/memberHistSchPage.do`(전직 의원 목록)의 XHR을 본다
2. **수집 중 명부에 없는 slug를 만나면 그 상세 페이지를 직접 받는다.** `/members/22nd/{slug}`가 퇴직 의원에게도 살아 있는지 확인이 필요하다

## 5. `tmprAnYn` 필드의 의미

의안 상세의 숨은 input에 있고 관측한 모든 의안에서 `N`이었다. 임시안 여부로 추정하지만 확인하지 못했다.

**모르면 저장하지 마라.** 의미를 모르는 컬럼은 나중에 누군가 잘못 해석한다.

## 계획 세션에서 해소한 것들 — 다시 재지 마라

근거 수치는 [02-데이터-원천.md](02-데이터-원천.md)에 있다.

| 초안의 질문 | 확인 결과 |
|---|---|
| 표결에 '불참' 명단 탭이 있는가 | **없다.** 찬성/반대/기권 셋뿐이고 응답에 '불참' 문자열이 아예 없다. 스키마의 `CHECK`와 "행 없음 ≠ 불참"이 맞다 |
| 재의결 법안의 표결이 두 번 오는가 | **한 번만 온다.** 상법 2208496(재의 대상)에 `재석`이 1회뿐. `bill_vote_summary` PK를 바꿀 필요가 없다 |
| 대표발의와 공동발의를 어떻게 가르나 | 상세 페이지 상단 **대표발의의원 카드**의 `/members/` 링크. 팝업은 대표발의를 전혀 표시하지 않는다 |
| 위원장·정부 제출의 발의자 | 대표발의 카드가 없고 `/members/` 링크도 없다. `proposer_kind`로 가른다 |
| 22대 최초 의안번호 | **2200001** |
| 의안번호가 정말 연속인가 | **전수 확인.** 20,510건이 2200001~2220510에 구멍 0·중복 0 |
| `PRC_` 코드의 문자 집합 | 속성에서 뽑으면 정확하다. 그리고 **정부제출은 `ARC_`다** |
| 법률명약칭 사전 | 1,034건 존재하나 커버리지가 낮고 언론 통칭이 없어 **사용 보류**로 결정 |

## 계획 세션이 새로 발견한 함정 — 초안에 없던 것

| 발견 | 영향 |
|---|---|
| **의안 상세는 서버렌더링이 아니다** — 심사 단계는 `billInfo.do` XHR로 온다 | 의안 1건에 요청 2회가 최소. 초안의 "XHR 없음" 서술이 틀렸다 |
| **정부제출 의안의 billId는 `ARC_`** (실측 470건) | `PRC_`만 가정하면 조용히 누락 |
| **`ZZ22124` 형식 의안번호 88건** | `bill_no`를 INTEGER로 두면 깨진다. TEXT로 바꿨다 |
| **`billGbnCd=대안`** 숨은 필드 | 대안 여부를 이름에서 추정할 필요가 없다 |
| 위원장 934건 · 정부 601건 · 재의 28건 | 규모 감각. `proposerKind`·`reexamYn`이 검색 필터로 있다 |
| 소관위 처리결과에 `대안가결`이라는 값이 있다 | 처리결과 값 집합이 본회의와 위원회에서 다르다 |
