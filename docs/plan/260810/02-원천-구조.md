# 02 — 원천 구조

2026-08-10에 Chrome으로 직접 열어 확인한 것이다. **추정이 아니라 실측이고, 확인한 URL과 뽑은 값을 그대로 적는다.**

## 1. 법률안

### 1.1 상세 페이지의 실제 구조

`https://likms.assembly.go.kr/bill/bi/billDetailPage.do?billId={billId}`

**본문은 클라이언트가 그린다.** 페이지 HTML을 그냥 받으면 `#insc-step-sect`가 비어 있다. 실제 내용은 이 요청이 준다.

```
POST https://likms.assembly.go.kr/bill/bi/bill/detail/billInfo.do
Content-Type: application/x-www-form-urlencoded
body: 페이지의 hidden input 전부 + billId
```

> ⚠️ **폼 전체를 보내야 한다.** `{billId, _csrf}`만 보내면 `Bad Request.` 12바이트가 온다. 이건 `rules/parsers.md`에 이미 적혀 있던 함정이고 여전히 유효하다.

응답(약 35KB)의 구조:

| H3 섹션 | H4 표 | `<td class>` |

| 심사진행단계 | — | `#insc-step-sect > div[data-gbn]` |

> **`.bill_memo`는 페이지에 하나뿐이다.** v2가 `head_memo`(목록 폼의 `headMemoInfo`)와 `status_memo`(이것)로 나눠 담았지만 화면상 같은 것이다 → [D2](01-진단.md#d2)

탭은 최대 셋이고 `a[data-tabnm]`으로 드러난다.

```

voteInfo   표결정보   (본회의 표결이 있을 때)
```

> ⚠️ **`본회의불부의` 의안에는 대안정보 탭이 없다.** 2219947·2200255 실측 `TABS: []`. 그 의안의 대안 관계는 **반대편**(그 대안의 `anBillInfo`가 흡수한 원안들을 열거)에서만 온다.

### 1.2 심사진행단계 위젯 — v3의 중심

`#insc-step-sect > div[data-gbn]`. **이것이 원천의 정본 어휘다.**

```html
<div class="" data-gbn="RECEIVE">
    <div class="title">접수</div>
    <div class="stepdate">2025-11-27</div>
</div>
<div class="icon_step_arrow"></div>
<div class="on" data-gbn="GOVTRANS">
    <div class="title">정부이송</div>
    <div class="stepdate">2026-07-31</div>
</div>
```

헤더의 안내문이 날짜의 뜻을 말해 준다.

> ※ 접수는 제안일자, 심사단계는 처리일자, 본회의는 의결일자 기준임

#### gbn 코드 7종

| gbn | 라벨 | 날짜 |
|---|---|---|
| `RECEIVE` | 접수 | 제안일자 |
| `CMT` | 위원회 심사 | 소관위 처리일 |
| `EXAM` | 체계자구 심사 | 법사위 처리일 |
| `MAIN` | 본회의 심의 | 의결일 |
| `GOVTRANS` | 정부이송 | 정부이송일 |
| `REEXAM` | **정부재의** | 재의요구일 |
| `DCS` | **가변** — 공포·대안반영폐기·수정안반영폐기·철회·폐기·부결 | 해당일 |

`class`는 셋이다: `""` 완료 · `"on"` 현재 · `"proc"` 예정(날짜 없음).

#### 실측한 진행 패턴 전수

여기서 읽어야 할 것 다섯:

**① 단계 목록은 의안마다 길이가 다르다.** 종결된 의안은 그 뒤가 잘리고(대안반영폐기는 3칸), 안 거친 단계는 빠진다(부결 2217099에 `CMT`가 없다).

**② `DCS`는 고정 라벨이 아니라 결말 그 자체다.** 미종결일 때만 `공포`(날짜 없음)로 표시된다.

**③ `재의부결`이라는 값은 원천에 없다.** `DCS:부결` + 앞의 `REEXAM:정부재의`다. → v3에서 `outcome='부결' AND date_reexam_requested IS NOT NULL`로 표현된다.

**④ `본회의불부의`도 원천 위젯에 없다.** 위젯의 오른쪽 끝 날짜가 `위원회 심사`에 머문다. 그 의안이 끝났음을 아는 근거는 **소관위 처리결과가 `대안반영폐기`인 것**과 **대안 관계가 있는 것** 둘뿐이다.

**⑤ `정부재의`는 위젯에만 있다.** 상세의 어떤 표에도 재의 관련 칸이 없고, `pre.bill_memo`의 산문에만 남는다.

### 1.3 표결정보

탭 `voteInfo`. `rules/parsers.md`가 적어 둔 함정이 그대로 유효하다 — **직전 `billInfo.do`가 만든 폼을 그대로 재사용해야 한다.** `{billId, _csrf}`만 보내면 400이 오고, 그게 "원천이 표결을 안 준다"로 오진된다.

### 1.4 발의자 팝업

같은 응답 안에서 원천이 총원을 스스로 선언한다.

```
pager_count_text   "191"
pager_pages_text   " (1/14 페이지)"
```

> ⚠️ **`page`가 마지막을 넘으면 에러가 아니라 마지막 페이지를 다시 준다.** 빈 응답을 종료 조건으로 쓰면 무한 루프다.

숨은 필드가 공동대표발의를 직접 말해 준다.

```html
<input id="info" value="최형두의원ㆍ이준석의원ㆍ황정아의원 등 11인">
```

> ⚠️ 중점이 두 종류다 — `ㆍ`(U+318D)와 `·`(U+00B7). 텍스트 진입점에서 정규화해야 같은 이름이 두 값이 되지 않는다.

### 1.5 제안자 칸이 주는 것 (`.proposer`)

```
의원   "이해민의원 등 13인"  + 제안자 목록 팝업 링크
위원장 "법제사법위원장"       링크 없음
정부   "정부"                링크 없음   ← 부처 정보가 없다
의장   "의장"                링크 없음
기타   "감사원장"            링크 없음
```

**정부 발의 601건은 원천이 어느 부처인지 안 준다.** 위원장 발의는 제목 끝 괄호에도 같은 값이 있고, 실측상 **언제나 소관위와 같다**(933/934, 불일치 0).

### 1.6 목록

`https://likms.assembly.go.kr/bill/bi/bill/sch/detailedSchPage.do?detailedTab=billDtl`

1,000행/요청에 1.9초. 전체 21요청 40초. 목록 표의 컬럼은 여덟이고 **의안종류(`bill_kind`)가 없다** — 그건 상세의 `billKindCd`에서만 온다.

> ⚠️ 목록 셀 앞에 `계류의안`/`처리의안` 배지 텍스트가 붙는다. 떼고 저장한다.

## 2. 국회의원

| 무엇 | URL |
|---|---|
| 현직 명부 | `https://open.assembly.go.kr/portal/assm/search/memberSchPage.do` |
| 전직 명부 | `https://open.assembly.go.kr/portal/assm/search/memberHistSchPage.do` |
| 상세 | `https://www.assembly.go.kr/members/{대수}/{openNaId}` |

- `open_na_id`는 상세 URL의 마지막 조각이고 표결·발의자·발언에 나오는 유일한 식별자다. 대소문자 규칙이 없다(`KIMHyun` · `CHOIMinhee` · `KANGKYUNGSOOK`) — **이름에서 만들어낼 수 없으므로 반드시 원천의 href에서 가져온다.**
- 현직/전직 판정은 상세 페이지의 `jeonzik_name` 클래스 유무다(전직이면 붙는다).
- 명부 JSON API는 **봇 차단(403)**이다 — curl·httpx·실제 크롬 전부. `mona_cd`의 유일한 출처였고, 그래서 v3에서 그 컬럼을 지운다.

> ⚠️ **두 호스트가 같은 의원을 다르게 로마자화한다.** record의 회의록은 `/members/22nd/JUNGHYEKYUNG`으로 링크하는데 www의 실제 slug는 `JEONGHYEKYEONG`이고 앞의 것은 404다. 실측 3명(정혜경·권향엽·김윤덕).
>
> ⚠️ **그렇다고 이름으로 합치면 안 된다 — 동명이인이 실재한다.** 22대에 박지원이 둘이고 둘 다 상세가 200이다. **죽은 slug(404)만** 합치기 대상이다.

## 3. 회의록

### 3.1 트리

`https://record.assembly.go.kr/assembly/mnts/total/22.do?class_id_sch={n}&cmit_chk=all`

화면에 여섯 섹션이 있다.

```
국회본회의 · 상임위원회 · 예산결산특별위원회 · 특별위원회 · 국정감사 · 국정조사
```

**본회의는 수집하지 않기로 했다.** 나머지 다섯이 `class_id_sch` 2·4·3·5·6이다.

> ⚠️ **같은 위원회가 두 섹션에 나타난다.** 국정감사는 상임위별로 열리므로 과방위 회의가 `상임위원회` 섹션에도 `국정감사` 섹션에도 있다. 이 값은 **회의의 성질**이지 위원회의 성질이 아니다 → [D5](01-진단.md#d5)
>
> ⚠️ 위원회 종류를 가르는 문자열이 회의록 본문 헤더 어디에도 없다. **그래서 열거 단계에서 id와 섹션을 쌍으로 들고 와야 한다** — "목록은 id만 열거한다"는 원칙의 유일한 예외다.

### 3.2 본문

`https://record.assembly.go.kr/assembly/viewer/minutes/xml.do?id={conference_id}&type=view`

헤더에서 회기·차수·위원회를 파싱한다. **형식이 종류마다 다르다.**

- 차수는 제목 줄이 아니라 `<p class="num">`에 있고 단위가 '차'가 아니라 '호'다(`제3호`)
- **국정감사(class 5)만 회기도 차수도 없다** — `2024년도 국정감사 …위원회회의록`. 그 부류는 `session_no`·`sitting_no`가 NULL인 것이 정상이다(317건)
- 대수는 헤더에 없다. 트리를 `th_sch=22`로 부르므로 요청 쪽 값을 쓴다

소위 판정은 **제목 줄의 '회의록' 뒤에 오는 괄호**다.

```
국회운영위원회회의록 (국회운영개선소위원회)                         → 소위
예산결산특별위원회회의록 (2025년도제1회…조정소위원회)               → 소위
대법관(노경필·박영재·이숙연)임명동의에관한인사청문특별위원회회의록  → 소위 아님
```

> ⚠️ **"괄호가 있으면 소위"로 만들면 틀린다.** 위원회명 자체에 괄호가 들어간다(id 52240). 소위 괄호는 언제나 '회의록' **뒤**이므로 거기에 앵커를 잡는다.

화자는 `.man` 블록 안에 `/members/` 링크가 있는지로 의원/비의원을 가른다. 실측 한 회의 105블록 중 61 의원 / 44 비의원. **직위 문자열로 분류하면 안 된다** — 종류가 열려 있고 회의마다 새로 생긴다.

> ⚠️ **2026-08 시점에 회의록 본문이 자기 id를 안 주기 시작했다.** `fetch_body`의 대조 가드가 무력해졌고, 그 상태로 받은 2,047건 중 28건이 다른 회의의 본문이었다. `verify.py`의 단언이 지금 빨간불이고, **그것이 정확한 상태 표시다.** v3 구현에서 이 가드를 다시 세워야 한다.

## 4. 원천이 안 주는 것

다음 세션이 찾아 헤매지 않도록 못 박는다.

| 없는 것 | 확인 |
|---|---|
| 정부 발의의 소관 부처 | 제안자 칸이 `정부` 세 글자 |
| 표결 불참자 명단 | 찬성·반대·기권만 준다. 불참은 재적−재석으로 **계산**한다 |
| 동명이인의 표결 구분 | 명단이 이름만 준다. 박지원 2명 때문에 61건이 1명씩 비는 것이 그 결과 |
| 소위원회명 (절반) | 원천이 빈 문자열을 보낸다. 16,434행 중 7,790행만 있다 |
