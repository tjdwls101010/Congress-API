# 05 — 하네스 정리

이 저장소의 하네스는 지금 일곱 컴포넌트다(B1~B7, `.claude/harness-spec.md`). v3에서 **둘을 제거하고 셋을 개정한다.**

## 제거

### `.claude/rules/parsers.md` (B7) — 제거

`paths: Scripts/*.py` 글롭이 붙어 있어 파서 파일을 열 때만 로드된다. 평소 컨텍스트 비용은 0이다.

**제거의 대가를 정확히 적는다.** 이 문서에는 이 프로젝트에서 실제로 데이터를 잃게 만든 함정만 담겨 있고, 지난 세션에서 발견한 결함 다섯 개 중 넷이 여기 적힌 함정의 재발이었다. 스키마 주석은 **조회하는 쪽**을 위한 것이라 파서 규칙을 담지 않으므로, 제거하면 그 교훈이 어디에도 안 남는다.

**그래서 제거하되 내용은 옮긴다.** 파서 규칙 중 원천의 사실인 것들은 이 계획서 [02-원천-구조.md](02-원천-구조.md)에 이미 흡수했다:

| `rules/parsers.md`의 규칙 | 옮긴 곳 |
|---|---|
| 폼 전체를 보내라 (`{billId,_csrf}`만 보내면 400) | 02번 1.1절 |
| JSON 엔드포인트를 먼저 확인해라 | 02번 1.1절 · 스키마의 `bills.committee` 주석 |
| 페이징 팝업은 총원을 스스로 선언한다 | 02번 1.4절 · 04번 5절 |
| `page`가 마지막을 넘으면 마지막을 다시 준다 | 02번 1.4절 |
| 표는 caption으로 찾고 값은 `<td class>`로 | 02번 1.1절의 클래스 표 |
| 캡션이 값을 담을 때가 있다 (체계자구) | 스키마의 `bill_stages.committee_name` 주석 |
| 이 원천은 공백·개행을 대량으로 넣는다 | 04번 5절 `members.py` |
| 정규식 대안에 catch-all을 넣지 마라 | 04번 5절 `members.py` |
| 중점이 두 종류다 | 02번 1.4절 · 04번 4절 |
| `expected`를 자기 길이로 주지 마라 | 04번 5절 `bills.py` |
| UPSERT의 `DO UPDATE SET`에 새 컬럼을 빠뜨리지 마라 | — (아래) |
| 성공하면 하위 실패를 반드시 지워라 | 스키마의 `collect_failures` 주석 |
| 삼항연산자는 `or`보다 우선순위가 낮다 | — (일반 파이썬 지식) |

옮기지 못한 둘은 **코드 주석으로 내린다** — `db.py`의 UPSERT 함수 옆과 `clear_failure` 옆.

> **구현 세션 주의**: 계획서는 구현이 끝나면 아무도 다시 안 읽는다. 파서를 다시 뜯는 미래 세션이 이 교훈을 못 보게 되는 것이 제거의 실제 비용이고, 그 비용을 받아들이기로 한 결정이다. **대신 함정 하나하나를 그것이 적용되는 코드 옆 주석으로 반드시 내려라.**

### `.claude/hooks/selftest-on-parser-edit.sh` (B5) — 제거

`Scripts/*.py` 편집마다 `db.py selftest`를 돌리는 `PostToolUse` 훅. 실행이 0.063초라 비용이 사실상 0이고, 지난 세션 기록에 따르면 파서 3종을 뜯는 구간 내내 초록불로 남아 헛울지 않았다.

**제거하면 `selftest`를 손으로 돌려야 한다.** v1의 `bill_kind` 회귀가 3시간 뒤에야 잡혔고 그 사이 게이트가 아무것도 검사하지 않으면서 초록불이었던 사고가 이 훅이 만들어진 이유다.

> **구현 세션 주의**: 훅이 없으므로 **`Scripts/*.py`를 고칠 때마다 손으로 돌려라.**
>
> ```bash
> uv run .claude/skills/congress/Scripts/db.py selftest --db /tmp/t.db
> ```
>
> ⚠️ `selftest`는 첫 동작이 **대상 DB 삭제**다. `--db`가 필수 인자이고 실제 `CONGRESS.db`를 지목하면 argparse가 거부한다. **그 가드를 완화하지 마라** — News 프로젝트에서 그렇게 4.25GB를 잃었다.

### `.claude/settings.json`의 hooks 절 — 제거

훅이 사라지므로 `hooks` 키를 통째로 지운다. `permissions`는 유지한다(B6).

## 유지

### `.claude/settings.json` — permissions (B6)

**편의이지 안전이 아니다.** 좁은 allow 규칙만 모든 권한 모드에서 작동하므로 경로까지 박은 현재 형태를 유지한다.

- `deny: Bash(git clean:*)` 유지 — `actions/checkout`의 `git clean -ffdx`가 gitignore된 DB를 지운 실제 사건을 겨눈다
- ⚠️ **`Bash(rm:*CONGRESS.db*)`를 다시 시도하지 마라.** Bash 규칙의 `:*`는 접두 매칭이라 중간 와일드카드가 성립하지 않고, 그 문자열은 **아무것도 매칭하지 않는다**

### `.github/workflows/` (B3·B4)

- `scheduled-collect.yml` — 하루 1회 수집
- `collect-watchdog.yml` — 맥 밖에서 수집 정지를 감시

> ⚠️ **DB를 체크아웃 안에 두지 마라.** `actions/checkout`은 기본으로 `git clean -ffdx`를 돌고 `-x`가 gitignore된 파일까지 지운다. `CONGRESS_DB`가 작업공간 밖 실제 경로를 겨눈다.
>
> ⚠️ **판정 결과를 파이프로 넘기지 마라.** `collect.py | tee`는 셸이 마지막 명령의 종료코드를 돌려주므로 게이트 위반의 1이 `tee`의 0으로 덮인다.
>
> 러너는 `~/actions-runner-congress-api` (`congress-api-seongjin-mac`)다. **`~/actions-runner-congress`는 이 저장소가 아니다** — `Congress-DB` 소속이니 건드리지 마라.

**갱신 시간이 늘어난다.** 계류 재수집이 1.5~2시간이므로 워크플로의 타임아웃과 락 회수 시간(`STALE_LOCK_MINUTES = 720`)을 확인할 것. 720분(12시간)은 여전히 충분하다.

## 개정

### `CLAUDE.md`

지금 7줄이고 라우팅만 담는다. **바꿀 필요가 없다.** 수집 주기도 그대로 하루 1회다.

### `SKILL.md`

스키마가 크게 바뀌므로 **스키마를 되풀이하는 서술을 전부 다시 쓴다.** 현재 143줄 중 다음이 낡는다.

| 낡는 서술 | 새 내용 |
|---|---|
| `bills.outcome` 9종 값과 분포 | 7종. 분포는 재수집 후 실측값으로 |
| `decision_result`·`reconsideration_result` 경고 | 컬럼이 없어졌다. **`재의부결`을 어떻게 찾는지**로 대체 |
| `review_status` 언급 | `current_stage`로 |
| `bill_stages` vs `bill_meetings` 표 | 유지하되 `bill_stages`에 result가 없다는 것 반영 |
| `bill_alternatives` 양방향 질의 | `bills.alt_bill_no`의 역조회로 |
| "발언에서 의원까지는 두 홉이다" | **한 홉이다.** `meeting_utterances.open_na_id` |
| 감사 지표 표 | 04번 6절의 새 게이트 목록으로 |
| 데이터 경계 | `mona_cd` 언급 삭제(컬럼이 없다), 정부 부처 없음 추가 |

**새로 들어가야 할 것**은 `current_stage`와 `outcome`의 관계다. 스키마 주석이 각각을 설명하지만, **둘을 함께 쓰는 법**은 스키마가 말할 수 없다.

```sql
-- 진행 중인 것의 위치를 묻는다
WHERE outcome = '계류' AND current_stage = '체계자구 심사'
-- 끝난 것의 결말을 묻는다
WHERE outcome = '공포'
-- 거부권을 겪은 것
WHERE date_reexam_requested IS NOT NULL
```

> **`SKILL.md`는 스키마가 말할 수 없는 것만 담는다.** 스키마를 되풀이하면 두 곳이 어긋나고, 어긋난 쪽을 아무도 모른다. 이 원칙은 v2에서 정한 것이고 유지한다.
