### `outcome`의 값 — 9종 → 7종

```
계류 · 공포 · 대안반영폐기 · 수정안반영폐기 · 철회 · 폐기 · 부결
```

- **`본회의불부의` → `대안반영폐기`에 병합.** 실측으로 319건 중 317건이 대안 관계를 갖고 그 대안의 결말이 예외 없이 `계류`(= 아직 본회의 전)다. 같은 운명의 두 시점이다
- **`재의부결` 삭제.** 원천 위젯은 그냥 `DCS:부결`이고 앞에 `REEXAM:정부재의`가 붙을 뿐이다. `outcome='부결' AND date_reexam_requested IS NOT NULL`이 그 부류다

### 판정 규칙

```
current_stage = 위젯에서 날짜가 있는 맨 오른쪽 칸의 라벨
outcome       = DCS 칸에 날짜가 있으면 그 라벨
                없는데 alt_bill_no 가 있으면 '대안반영폐기'
                그 밖은 '계류'
```

**유도 규칙이 없다 = 유도 버그가 없다.** v2의 `derive_outcome()`이 `review_status='재의(가결)'`를 몰라 공포된 법안 1건을 `계류`로 판정하고 있었고, 이 전환이 그걸 구조적으로 없앤다.

## bill_stages — 7컬럼 → 6컬럼

`bill_no` · `stage` · `seq` · `committee_name` · `date_referred` · `date_processed`

- `stage` ∈ (`소관위`, `소위`, `체계자구`, `본회의`) — 원천의 '심사정보' 표 하나 = 한 행
- **`result` 삭제** — `outcome`을 위젯이 직접 주므로 유도에 안 쓰인다
- **`date_presented`(상정일) 안 만든다** — 원천에 있지만 지엽적
- **`관련위` 안 담는다** — 원천이 위원회명·회부일만 주고 나머지 칸을 빈 채 보낸다
- **소관위 회부일은 유지한다.** 제안일+1~3일이라 유도 가능하지만, **소위 회부일이 계류 10,990건의 유일한 진행 표지**라 컬럼을 지울 수 없다

> 계류 14,788건 중 처리일이 하나라도 있는 것은 994건(6.7%)뿐이다. 처리일만 담으면 나머지 13,794건이 전부 `접수`로 뭉개져 구별되지 않는다.

## 삭제되는 테이블 둘

### `bill_alternatives` → `bills.alt_bill_no`

원안 4,158건 중 4,156건이 대안 1개다. 2개인 2건을 열어 보니 **무관한 대안이 섞인 수집 버그**였다(2200057 방송문화진흥회법 → 위안부 피해자법 대안). **컬럼은 값을 두 개 못 담아 그 오염이 구조적으로 불가능하다.**

역방향("이 대안이 무엇들을 흡수했나")은 `WHERE alt_bill_no = ?` 역조회로 그대로 된다.

### `meeting_speakers` → `meeting_utterances`에 합침

`speaker_no`가 "사람의 식별자가 아니고 회의 밖에서 참조하면 안 되는 값"이라 읽는 쪽이 매번 배워야 하는 개념이었다. 비용은 **+38MB(633MB 기준 +6%)** — 테이블 하나와 두 홉 조인을 없애는 값으로 싸다.

## committees — 4컬럼 → 2컬럼

`committee_name` · `parent_committee`

- **`committee_class` 삭제.** 회의록 트리의 섹션은 **회의의 성질**이지 위원회의 성질이 아니다 — 국정감사는 상임위별로 열려서 과방위가 두 섹션에 나타나고, v2는 그 값을 위원회에 써서 **상임위원회 17개 중 14개가 `국정감사`로 굳었다**

## 갱신 전략

**`outcome='계류'`인 의안의 상세를 매 실행 전부 다시 받는다.** 종결된 것은 건드리지 않는다.

```sql
-- 재수집 대상
WHERE outcome = '계류'
```

- v2의 3갈래 조건(`detail_collected_at IS NULL` / `< updated_at` / `계류 AND 30일`)이 한 줄이 된다
- 목록만으로는 소위 이동을 **원리적으로** 못 잡는다(소위 회부돼도 `review_status`가 안 바뀐다). 30일 주기는 그 구멍을 막은 게 아니라 30일로 줄인 것
- 비용 **1.5~2시간/일**. 발의자·표결은 계류 재수집에서 뺀다(안 바뀐다). 계류 → 종결로 넘어가는 그 한 번에만 전부 받는다
- 의원 323명도 매 실행 전원 재수집

## 이 세션에서 하지 않기로 한 것

명시적으로 버린 것들이다. 다음 세션이 "이건 왜 없지"를 다시 묻지 않도록.

| 안 담는 것 | 이유 |
|---|---|
| 상정일 (`presentDt`) | 원천에 있지만 지엽적 |
| 문서 링크 (검토보고서·심사보고서·의안원문 PDF) | 지엽적. 본문을 읽을 계획이 없다 |
| 관련위 심사정보 | 원천이 위원회명·회부일만 주고 나머지를 빈칸으로 보낸다 |
| 본회의 회의록 | 실질 논의는 상임위·소위에서 일어난다 |
| 단계별 처리결과 | `outcome`을 위젯이 직접 주므로 유도에 불필요 |
| 정당 변경 이력 | 수집 시작 이전의 변경이 웹사이트에 없어 채울 수 없다 |
| 정부 발의의 소관 부처 | 원천이 `정부` 세 글자만 준다 |
| `bills.url` | `bill_id`에서 조립된다. 주석에 템플릿만 적는다 |
